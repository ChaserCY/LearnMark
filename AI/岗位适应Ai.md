# 🧠 对 AI 使用能力的分层（真实工作视角）

## 🟢 Level 1：工具使用者（入门）

**关键词：会问、会用、会复制**

你能做到：

- 用 AI 写代码片段
- 让 AI 解释报错
- 生成简单函数 / UI / SQL
- 做简单重构

但特点是：

- 只能“点状使用”
- 不会系统性设计任务
- 产出需要人工大量修正

👉 在大厂里，这个层级通常只算“刚开始会用工具”。

---

## 🟡 Level 2：任务加速器（合格工程师）

**关键词：拆任务 + 驾驭 AI + 验证结果**

你能做到：

- 把一个需求拆成 AI 可执行模块
- 用 AI 写“可运行的功能模块”
- 能判断 AI 代码是否正确
- 会做 prompt iteration（反复调教）
- 会让 AI 写测试 / debug / review

典型行为：

> “这个需求我先拆 5 个子模块，让 AI 分别实现，然后我做整合”

👉 这是大厂**主流工程师应达到的最低 AI 能力线**

---

## 🟠 Level 3：AI 协作开发者（中高级工程师）

**关键词：系统设计 + AI协同生产**

你能做到：

- 用 AI 参与系统设计（而不是只写代码）
- AI 写 60%~80% 代码，你负责架构与质量
- 用 AI 做：
    - code review
    - 性能分析
    - bug root cause 推理
- 会设计 prompt 规范（团队级）

典型模式：

> “我不写实现，我定义架构 + 接口 + 约束，AI负责实现细节”

👉 在大厂里，这是**核心生产力工程师**

---

## 🔴 Level 4：AI 驱动型工程师（高级/Tech Lead）

**关键词：用 AI 放大团队能力**

你能做到：

- 用 AI 改造开发流程（CI/CD + AI）
- 设计 AI coding standards（团队规范）
- 构建内部 AI 工具链（codegen / agent / review bot）
- 让团队“人 + AI”协作提效

典型行为：

> “我们不是用 AI 写代码，而是用 AI 重构研发流程”

👉 这是大厂真正稀缺的人

---

## ⚫ Level 5：AI 系统设计者（架构/研究/专家）

**关键词：AI 作为系统组件**

你能做到：

- 设计 multi-agent 工作流
- 构建自动开发系统（AI 写代码 + 测试 + 部署）
- 优化模型调用成本/延迟/可靠性
- 做 AI 工程基础设施

👉 这是“AI-native 工程体系”的设计者

---

# 🧩 大厂真实要求（总结一句）

现在主流标准是：

> ❗不是“会不会用 AI”，而是“你能不能用 AI 把生产力提高 2～10 倍，并且保证质量可控”。

---

# 🎯 对你（UE / 游戏客户端开发）更现实的标准

结合你做 UE / Puerts / UnLua 这类工程，大厂更看重：

### ✔ 必须具备

- 用 AI 写 gameplay / tool / editor 扩展代码
- 用 AI 做 Blueprint ↔ C++ 转换辅助
- 用 AI debug crash / log / replication bug
- 能检查 AI 写的 Unreal 代码是否“真能跑”

### ✔ 加分能力

- 用 AI 生成系统设计（技能系统 / ECS / GAS）
- 用 AI 做 Lua / TS binding 对照与迁移
- 用 AI 做性能分析建议（tick / GC / replication）

---

# ⚠️ 一个很重要的现实

大厂真正害怕的不是：

> “不会用 AI 的人”

而是：

> “只会用 AI，但不理解系统的人”

因为这种人：

- 写得快
- 但容易埋雷
- 后期成本更高

---

# 🚀 最核心一句话总结

> 大厂希望的不是“AI使用者”，而是“能用AI扩大工程能力边界的人”。


# AI屎山原因
模型： AI幻觉：生编硬造； 
推理偏移：写着写着跑偏了，写到其他的方向上，多了很多完全没用的东西； 
对UI操作困难：当前对于UI操作来说还是很难，这就缺少了操作软件来调试 
用户： 标准模糊：用户没有把问题的标准说详细，定义没说清楚，颗粒度没对齐，人和AI理解的东西没对上， 
工具和环境： 缺乏闭环：没有给AI闭环检测的工具，缺少测试 
没有项目记忆：缺少项目记忆，导致逐渐失去对项目开发的把握，一些习惯、约束，都没有记住； 
缺少智能体编排：没有多个AI进行对抗性检测、补盲，探索，其实单一智能体的视角和能力很受限； 
工具受限：受限于Agent的工具限制
