# Script， 跑(不会消耗Token)
## 可运行文件类型
- 直接：
	- SKILL 源文件（核心类型）
	- SKILL 编译文件（高性能）
	- Cadence EDA 配置文件（特殊 SKILL 脚本）
- 间接：
	- 脚本类文件(sh,py,cmd....)
	- 可执行二进制文件(exe)
	- 文本类文件（非 “运行”，但可读取处理）
## 不可运行的文件类型
- 非 SKILL 语法的乱码 / 二进制文件（如`.o`、`.so`、`.dll`，需编译为可执行文件后间接运行）；
- 加密文件、非标准格式的自定义配置文件（SKILL 无解析能力）；
- 他 EDA(电子设计自动化) 工具的专属文件（如`.oas`、`.gds`，只能通过 Cadence 内置函数加载，而非 “运行”）。
## 特点：
Agent SKILL 中的Script 只会执行，不会读取
同样是，总的SKILL条件触发

# SKILL与MCP
- **MCP（Model Context Protocol，模型上下文协议/应用层）** 是 Anthropic 于 2024 年 11 月推出的==**开源标准化通信协议**==，核心作用是为大语言模型（LLM）与外部工具、数据源和服务之间提供**统一的交互接口**，解决 AI 应用开发中 "集成碎片化" 和 "能力孤岛" 问题，被誉为 AI 领域的**USB-C 通用接口**Anthropic。
- **AI Agent 是介于用户和大模型之间的「智能中介 + 自主执行者」**，它不是简单的 “传声筒”，而是具备**目标导向、自主决策、工具调用能力**的 “工作智能助手”，能直接对接外部工具 / 系统，完成复杂任务闭环。

### 1. 什么是 MCP？

**MCP (Model Context Protocol)** 是由 Anthropic（Claude 的开发商）在 2024 年底发布的一套开放标准。

- **背景**：以前，如果你想让 AI 读取你的本地数据库、查看你的 Google Drive 或者操作你的虚幻引擎，每个开发者都要写一套专门的、互不通用的代码（插件）。
    
- **作用**：MCP 规定了一套统一的“语言”。只要工具开发者提供一个 **MCP 服务器**，任何支持 MCP 的 AI 客户端（如 Claude Desktop、OpenClaw、IDE 插件）就能直接“插上电源”，立刻获得这个工具的能力。

### 2. MCP服务器官方核心定义

**MCP 服务器（MCP Server）** 是一个**轻量级的可执行程序或脚本**，它通过标准化的模型上下文协议（MCP）向客户端（如 Claude Desktop、IDE 或像 OpenClaw 这样的 Agent 框架）公开**本地数据源**和**工具能力**。

官方文档中的一句话概括：

> "MCP Servers are the 'data providers' that expose specific resources, tools, and prompts to Large Language Models."  
> （MCP 服务器是向大语言模型公开特定资源、工具和提示词的“数据提供者”。）

---

### 2. 官方定义的“三大支柱”

官方规范要求一个 MCP 服务器必须（或可以选择）提供以下三种核心接口，AI 才能理解并使用它：

- **Resources（资源）**：
    
    - **定义**：只读的数据源。
        
    - **例子**：本地文件内容、数据库中的记录、API 返回的文档。
        
    - **AI 视角**：AI 可以“看到”并读取这些信息，类似于给 AI 开放了阅读权限。
        
- **Tools（工具）**：
    
    - **定义**：可执行的函数/动作。
        
    - **例子**：运行一段 Python 代码、发送一封邮件、执行 Git 提交、或者控制你的虚幻引擎运行。
        
    - **AI 视角**：AI 可以“执行”这些操作，让 AI 具备了动手能力。
        
- **Prompts（提示词模板）**：
    
    - **定义**：预设好的对话引导。
        
    - **例子**：一段专门用于“分析 C++ 内存泄漏”的复杂指令模板。
        
    - **AI 视角**：用户可以快速调用专家级的指令集，优化 AI 的回复质量。
        

---

### 3. 官方架构模型：它是怎么工作的？

官方将整个生态分为三层，MCP 服务器处于中间位置：

1. **MCP Host (宿主/客户端)**：这是 AI 交互的地方。例如 **OpenClaw**、Claude Desktop。
    
2. **MCP Server (服务器)**：这就是你问的东西。它是连接 AI 和现实世界的桥梁。
    
3. **Local/Remote Data & Tools (底层数据/工具)**：你的 K 盘、你的 GitHub 账号、你的 UE 5.6 编辑器。
    

**通讯流程：**  
用户在 **OpenClaw**（客户端）说话 -> OpenClaw 询问 **MCP 服务器**：“你能帮我读一下 K 盘的文件吗？” -> **MCP 服务器** 读取文件并返回给 OpenClaw -> OpenClaw 把文件喂给 **MiniMax/Claude**（大脑）。

---

### 4. 为什么要叫“服务器”？（技术本质）

虽然叫“服务器”，但它通常**不是**跑在远端云平台的。

- **本地性**：大多数 MCP 服务器其实就是你电脑上的一个 main.py 或 index.js。
    
- **通讯协议**：它之所以叫服务器，是因为它和客户端之间通过 **JSON-RPC** 协议进行通讯（通常基于标准输入输出 stdio 或 SSE 网络流）。
    

---

### 5. 官方定义的意义：解决“驱动程序”混乱

在没有 MCP 之前，如果你写了一个能控制虚幻引擎的 AI 工具，它只能在你的软件里用。  
**官方定义 MCP 的目的**：是让这个工具变成一个“标准驱动”。

- 只要你写了一个 **UE-MCP-Server**，那么 OpenClaw 可以用它，Claude Desktop 也可以用它，VS Code 也能用它。
    

### 总结

**MCP 服务器** 的官方定义是：一个遵循 MCP 标准、将**非公开数据**（你的本地文件）和**具体操作指令**（发邮件、写代码）封装成 **AI 可理解接口** 的中介程序。
