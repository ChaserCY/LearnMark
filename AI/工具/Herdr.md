#### 1. Workspace（工作空间 / 你界面里的 spaces）

- **定位**：Herdr 最顶层的项目容器，对应你本地的一个项目文件夹
- **核心作用**：隔离不同项目，保存项目级的所有配置（默认 AI 代理、环境变量、面板布局、标签页结构）
- **关键特点**：
    
    - 可以是普通文件夹，也可以是 Git 仓库根目录
    - 生命周期最长，只要不删除就永久保留
    - 你截图左侧的 `PTGAS` 就是一个 workspace，绑定了你的 UE5 项目目录
    

#### 2. Worktree（工作树）

- **定位**：**特殊类型的 workspace，基于 Git worktree 技术的分支级子工作空间**
- **核心作用**：给同一个 Git 仓库创建多个独立分支的工作目录，让多个 AI 代理并行开发不同分支，不会互相污染代码文件
- **关键特点**：
    
    - 从属于一个「主仓库 workspace」，在侧边栏会和主项目编组显示
    - 每个 worktree 对应一个 Git 分支，共享同一个 `.git` 仓库，但代码文件完全独立
    - 比如主项目是 master 分支，你可以创建一个 dev 分支的 worktree，AI 在 dev 上改代码，主目录始终保持干净
    
- 和普通 workspace 的区别：普通 workspace 是独立文件夹；worktree 是 Git 仓库的 “分支分身”，必须依附主仓库存在herdr.dev

#### 3. Session（会话）

- **定位**：**单个 AI 代理的一次运行实例**，运行在 workspace /worktree 内部
- **核心作用**：保存一次任务的完整上下文（对话历史、执行过的命令、修改的文件、任务进度）
- **关键特点**：
    
    - 同一个 workspace /worktree 里可以同时开多个 session，每个对应一个任务、一个代理
    - 支持暂停、恢复、关闭后重建（就是设置里的 `session restore` 功能）
    - 比如你在 PTGAS 项目里，开一个 session 写 UI 功能，另一个 session 查崩溃 bug，两者上下文完全独立
    
- 和 workspace 的区别：workspace 是 “项目文件夹 + 全局配置”，session 是 “里面的一次 AI 对话任务”

#### 4. Plan（计划）

- **定位**：**AI 代理的一种工作模式 / 工作流指令**，存在于 session 内部
- **核心作用**：让代理先做完整的任务拆解、步骤规划、风险评估，你确认后再动手改代码，避免盲目修改
- **关键特点**：
    
    - 通过 `/plan` 命令触发，是单次任务里的一个阶段
    - 不是独立容器，就是 session 里的一个功能流程
    - 比如你让代理 “加个设置界面”，输入 `/plan` 后它会先列出来要改哪几个文件、每步做什么、有什么坑，你确认后它再执行
    
- 和 session 的区别：session 是 “整次对话的全程”，plan 是 “对话里的规划环节”

---

### 一句话串起来（以你的 PTGAS 项目为例）

你把 `PTGAS` 文件夹加进 Herdr → 这是一个 **Workspace**（master 分支）；

你怕改坏主分支，创建了 `feature-tts-ui` 分支的 **Worktree** 来开发新功能；

你在这个 worktree 里启动 Claude 代理做 “重做 TTS 设置界面” 的任务 → 这是一个 **Session**；

你怕代理乱改，先输入 `/plan` 让它出实现方案，确认后再写代码 → 这个出方案的流程就是 **Plan**
