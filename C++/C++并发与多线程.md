# 第一节
## 一，并发，进程，线程的基本概念和综述
### 并发和并行：
- 什么是并发 (Concurrency)？
	- 并发是指==**处理多个任务的能力**==。在一个时间段内，多个任务都处于启动、运行到完成之间的某个状态，但**在任意一个时刻，可能只有一个任务在真正执行**。
	- 以往计算机，单核cpu（中央外理器）：某一个时刻只能执行一个任务：由**操作系统**调度，每秒钟进行多次所谓的“任务切换”(切换的快，就会造成同时进行的假象)。
	- 这种切换(上下文切换)是要有时间开销的，比如操作系统要多次保存你切换时的各种状态，执行进度等信息，都需要时间，一会切换回来需要复原这些信息。(核越多性能不一定越好，并且还要看程序对象的核运用)
	- 使用并发的原因：主要就是同时可以干多个事，提高性能；(1234,1234,1234)

- 什么是并行 (Parallelism)？
	- 并行是指==**同时执行多个任务的能力**==。这需要硬件支持，即拥有多个CPU核心或多个处理器。 多个任务在**同一时刻，真正在不同的CPU核心上同时运行**。

### 可执行程序
- 概念：磁盘上的一个文件
	- Windows下，一个扩展名为.exe的。
	- Linux下，ls -al, rwxrwxrwx(x执行权限)

### 进程
- 概念：
	- 可执行程序运行起来，就是创建了一个进程(==正在进行==的程序)
	- 进程是操作系统进行**资源分配和调度的基本单位**。当你启动一个应用程序时（比如打开一个浏览器），操作系统就会创建一个进程。
- 创建进程：
	- windows下，双击一个可执行程序来运行。
	- Linux下，./文件名  ./a
![](图片/C++/C++并发与多线程/IMG-20251229172105462.png)
### 线程
- 概念：
	- 线程是**CPU调度和执行的基本单位**。它被包含在进程之中，是进程中实际运行的“实体”
	- 每个进程（执行起来的可执行程序），都有一个==主线程==，这个主线程是唯一的，也就是一个进程中只能有一个主线程。当你执行要给可执行程序，产生了一个进程后，这个主线程就随着这个进程默的启动起来了；（与main函数共存亡） 
- 理解：
	- 线程是用来执行代码的
	- **线程**是一条代码的执行通路(道路)，代码执行完，线程结束
	- **进程的核心作用，就是作为“资源容器”，为它内部的所有线程提供一个安全、独立、完整的运行环境。** 它本身不干活，但它圈定了一块地盘，并把所有生产资料都准备好。
- 多线程
	- 并发/并行执行与自身程序无关，由操作系统根据硬件条件来确定是并发/并行
	- 线程并不是越多越好，每个线程都需要一个独立的堆栈空间，切换时要保存很多中间状态；
	- 切换会耗费本该属于程序运行的时间

## 二，并发的实现方法
### 实现并发的手段
- 通过多个**进程**实现并发
	- word启动后就是进程。ie浏览器启动后就是个进程。
	- 账号服务器，游戏逻辑服务器。 服务器进程之间的通信。
	- 进程之间通信(同一个电脑上:管道，文件，消息对列，共享内存);
	- 不同电脑上:socket通信技术;
- 在单独进程中，创建多个线程实现并发
	- 线程:感觉象轻量级的进程。每个线程都有自己独立的运行路径，但是一个进程中的所有线程共享地址空间(共享内存)
	- 全局变量，指针，引用 都可以在线程之间传递,所以:使用多线程开销远远小于多进程。
	- 共享内存带来新问题，数据一致性问题;线程A，线程B;
- 总结：
- 线程优点：==启动，执行快，开销少，更轻==
	- 线程启动更快，更轻量级
	- 系统资源开销更少，执行速度更快，比如共享内存这种通信方式比任何其他的通信方式都快
- 缺点：==数据一致性问题==

# 第二节
## 一，线程的开始运行和结束
### 标识：
1. 主线程从main()开始执行，那么我们自己创建的线程，也需要从一个函数开始运行(初始函数)
2. 整个进程是否执行完毕的标志是 主线程是否执行完，如果主线程执行完毕了，就代表整个进程执行完毕了。此时，一般情况下:如果其他子线程还没有执行完毕，那么这些子线程也会被操作系统强行终止。
3. 一般情况下，我们得到一个结论:如果大家想保持子线程 (自己用代码创建的线程)的运行状态的话，那么大家要让主线程一直运行==(也有例外)==
### 操作：
1. 包含一个头文件thread（==#include\<thread>==）
2. 写一个初始函数
3. main中开始写代码
### 意识：
1. 在main中创建一个线程后，相当于程序有两条线同时在走（并发），即使一条线出问题，不影响另一条线
2. 如果主线程执行完毕，但必要的子线程没有执行完毕，程序不稳定， 那么是不合格的

# 第三节
## 一，传递临时对象作为线程参数
```cpp
#include <iostream>
#include<thread>
using namespace std;

//void myprint(const int& i, char* pmybuf)
void myprint(const int& i, const string &pmybuf)
 {
    cout << i << endl; //分析：i并不是mvar的引用，实际是值的传递，即便主线程detach了子线程，那么子线程还是安全的
     
    cout << pmybuf.c_str() << endl;  //指针在detach子线程时，绝对会有问题 
    return;
}

int main() {
    
   //一：传递临时对象作为线程参数
    int mvar = 1;
    int& mvary = mvar;
    char mybuf[] = "this is a test！";
    thread mytobj(myprint, mvar, mybuf);//存在main执行完了，系统才用mybuf去转string
    thread mytobj(myprint, mvar, string(mybuf));
    mytobj.detach();
    // mytobj.join();
    cout << "I Love China"<<endl;
    return 0;
}
```

### 陷阱一：
- 在线程thread中，const int& i，你传递mvar时，线程会自动拷贝一份mvar的副本，函数里的const int& i实际引用的是这个 “副本”，而不是main里的原始mvar
- 在**非多线程的普通函数调用场景**中，`const int& i`（或`int& i`）**没有副本**，直接绑定值本身
- 函数参数传递指针，指针在detach子线程时，绝对会有问题 
### 陷阱二：
- mybuf到底是在什么时候转换成string。存在main执行完了，系统才用mybuf去转string
-  只要引用临时构造的A类对象作为参数传递给线程，那么就一定能在主线程结束之前构造出来
- ==这个转换是主线程的一部分==,==而隐式转换是子线程的部分==
### 总结：
- 若传递int这种简单类型参数，建议都是值传递,不要用引用。防止节外生枝。
- 如果传递类对象，避免隐式类型转换，全部都在创建线程一行构建出临时对象来，然后在参数里用引用来接
- 建议不用detach（），就不存在局部变量失效导致线程对内存的非法引用问题
## 二，临时对象作为线程参数
- 线程id概念:id是个数字，每个线程(不管是主线程还是子线程)实际上都对应着一个数字，而且每个线程对应
- 也就是说，不同的线程，它的线程id(数字)必然是不同;线程id可以用c++标准库里的函数来获取。std::this_thread::get_id（）来获取;
## 三，传递类对象，智能指针作为线程参数
- 正常情况下，类对象引用传递进去，会进行拷贝，导致无法通过引用来修改
- 使用==std::ref()==  包裹传递参数
- &*myobj *== std::ref(*myobj*)
- 使用智能指针（操作相同内存地址）
	- unique_ptr\<int> myp(new int(100));智能指针声明
	- void myprint3(unique_ptr\<int> pzn){}; 智能指针参数
