## 同步与异步
- **同步（同步）**：
    - 指一个任务的执行必须依赖于前一个任务的完成。
        
    - **行为特征**：**阻塞 (Blocking)**。调用者发出请求后，必须死等结果返回，期间不能做任何其他事情。
        
    - 代码表现：int res = func(); （下一行代码必须等 func 跑完才能执行）。
        
- **异步 （Asynchronous）：**
    - 指一个任务的执行不需要等待前一个任务完成。
        
    - **行为特征**：**非阻塞 (Non-Blocking)**。调用者发出请求后，**立刻返回**去处理别的事。当结果准备好时，通过 **回调 (Callback)**、**通知 (Event)** 或 **轮询 (Polling)** 来告知调用者。
        
    - 代码表现 ：std：：async（func）; 或 socket.read_async（缓冲区，回调）;。

# C++ 项目全景图

想象你在**组装一辆汽车**：
## **第一阶段**(制造阶段，代码->exe):
 1. **预处理**：把设计图纸（代码）上的所有“参考第X页”都拿过来拼成一张完整的超大图纸。
    -  **输入**：.cpp 源文件，.h头文件。
	- **做什么**：它是文本替换工，==(补全cpp代码文件)==。
	    - 处理所有以 # 开头的指令。
	    - 把 \#include <...> 的头文件内容直接**复制粘贴**到你的 .cpp 文件里。
	    - 把 \#define 定义的宏替换掉。
	    - 删掉所有注释。
	- **输出**：一个巨大的、纯 C++ 代码的临时文件（通常叫“翻译单元”）。
	- **.h文件**：
		 ![](图片/C++/知识/IMG-20260208173002509.png)
		 ![](图片/C++/知识/IMG-20260208174526277.png)
2. **编译**：工厂根据图纸，制造一个个独立的零件（.obj），比如引擎、轮胎、车门。引擎组不管轮胎怎么造，只管造引擎。
	- **输入**：预处理后的文件。
	- **做什么**：它是“翻译官”**。==(cpp单个文件代码->机器码obj)==
	    - 检查语法错误（漏分号、拼写错误）。
	    - 把 C++ 代码翻译成**汇编语言**（Assembly）。
	    - 再把汇编语言翻译成机器能看懂的**机器码**（010101）。
	    - **注意**：编译器是“只看眼前”的，它单独编译每一个 .cpp 文件，==互不干扰==。它不知道其他 .cpp 里的东西，只要头文件里声明了“有这个东西”，它就信了。
	- **输出**：**目标文件（Object File）**。
	    - Windows 上是 .obj
	    - Linux 上是 .o
     
3. **链接**：总装车间把所有零件拼在一起。
    - **静态链接**：把收音机直接焊死在车上。
    - **动态链接**：留一个USB口，车跑起来的时候再插上外接设备（DLL）。
    - **输入**：所有的 .obj 文件 + **静态库（.lib / .a）**。
	- **做什么**：它是**“装配工”**。(==拼obj->exe==)
	    - **合并**：把你所有的 .obj 文件拼在一起。
	    - **填空（Resolve Symbols）**：编译器留了很多“坑”。比如你在 A.cpp 调了 B.cpp 的函数，编译时 A.obj 里那个位置是空的（或者是占位符）。链接器负责找到 B.obj 里的函数地址，填进 A.obj 的坑里。
	    - **静态链接**：如果你用了静态库（比如 libcurl.a），链接器会把库里的代码**抄一份**塞进你的 EXE 里。
	- **输出**：最终的**可执行文件**（Windows .exe / Linux ELF）。

## 第二阶段(运行阶段，从硬盘到内存)
1. **加载**：把造好的车（EXE）从仓库（硬盘）开到赛道（内存）上。
    - **角色**：操作系统的加载器（Loader）。
	- **做什么**：(==操作系统把exe读取到内存==)
	    - **搬家**：把硬盘上的 EXE 文件读取到**内存（RAM）**中。
	    - **动态链接**：如果你的程序依赖**动态库**（Windows .dll / Linux .so），加载器会检查这些 DLL 只有没有加载。如果没有，就去硬盘找并加载进来；如果有，就把你的程序和这些 DLL 连起来（填好最后的地址坑）。
     
2. **运行**：
    - **栈**：车手的临时口袋（装车钥匙、零钱），下车就清空。
    - **堆**：后备箱（装大件行李），下车时如果忘了拿出来，就永远丢在车里了（内存泄露）。
    - **操作系统**：赛道管理员，只有他允许，你才能踩油门。
    - **角色** ：CPU。(==CPU按规则执行每行代码==)
	- **做什么**：
	    - OS 把 CPU 的指挥权交给你的程序的入口（通常是 main 函数）。
	    - CPU 一行行执行代码段里的指令。
	    - **系统调用**：当你需要读文件、发网络包、打印到屏幕（cout）时，你的程序没有权限直接操作硬件，必须通过 **系统调用（System Call）** 请示操作系统（Kernel）代劳。

# 智能指针
==std::unique_ptr=**裸指针**+**自动销毁**+**禁止复制**==
C++11 标准库（==`<memory>`== 头文件）提供了三种智能指针，分别应对不同的场景。
#### 1. `std::unique_ptr` （独占型）
==using PtrType = std::unique_ptr<T, std::function<void(T*)>>;==自定义删除函数(没有自动delete)
**“这块内存是我的，谁也别想抢。”**//在}结束后，自动释放
这是最常用的智能指针（占 80% 场景）。它保证同一时刻只能有一个指针拥有这块内存。

- **特点**：
    - **不能复制**（你不能 `t2 = t1`，否则会有两个主人，乱套了）。
    - **只能移动**（`std::move`），所有权转移。
    - **轻量级**：性能和裸指针几乎一样，没有额外开销。
- **代码示例**：
```cpp  
    #include <memory>

    void testUnique() {
        // 创建方式：推荐使用 std::make_unique (C++14)
        std::unique_ptr<int> ptr1 = std::make_unique<int>(100);
    
        // std::unique_ptr<int> ptr2 = ptr1; // ❌ 报错！禁止复制
        
        // 所有权转移：ptr1 变空了，ptr2 接管内存
        std::unique_ptr<int> ptr2 = std::move(ptr1); 
    
        // 离开作用域时，ptr2 自动释放内存，ptr1 因为是空的啥也不干
    }
```

#### 2. `std::shared_ptr` （共享型）
**“这块内存是我们大家的，最后一个走的记得关灯。”**
这就是能解决你刚才多线程崩溃问题的神器。
- **特点**：
    - **引用计数**：内部维护一个计数器。每多一个指针指向这块内存，计数器 +1；销毁一个指针，计数器 -1。
    - **自动销毁**：当计数器变为 0 时，真正的内存才会被释放。
    - **可复制**：可以传给函数、传给线程，大家一起用。
- **代码示例**：
```cpp
    void testShared() {
        // 创建方式：推荐 std::make_shared
        std::shared_ptr<int> ptr1 = std::make_shared<int>(200); 
        // 此时计数 = 1
    
        {
            std::shared_ptr<int> ptr2 = ptr1; 
            // 此时计数 = 2 (ptr1 和 ptr2 共享)
            std::cout << *ptr2 << endl; 
        } // ptr2 离开作用域，计数 -1，现在计数 = 1
    
        // ptr1 依然活着，内存没释放
    } // ptr1 离开作用域，计数 = 0 -> 释放内存！
```
    
- **回到你的多线程问题**：  
    如果你把 `int a` 换成 `std::shared_ptr<int> a`，然后按值传递给线程。线程会持有一份计数。即使主线程结束了，只要子线程还握着这个指针（计数 > 0），内存就不会释放，程序就不会崩！
    

#### 3. `std::weak_ptr` （旁观者）
**“我就静静地看着，不参与管理。”**
它是为了配合 `shared_ptr` 而存在的，专门解决**“循环引用”**导致的死锁问题。
- **场景**：对象 A 里面有个 `shared_ptr` 指向 B，对象 B 里面有个 `shared_ptr` 指向 A。
    - 结果：A 等 B 释放才释放，B 等 A 释放才释放。谁也死不了，内存永远泄漏。
- **用法**：`weak_ptr` 指向 `shared_ptr` 管理的对象，但**不增加引用计数**。如果想用数据，必须先“转正”变成 `shared_ptr`（检测对象是否还活着）。

# &
### 1. 身份一：引用（Reference）

**口诀：出现在“类型”旁边，就是引用。**

> 在 C++ 中，Log& 表示 **引用类型（Reference Type）**。  当函数的返回值类型写成 Log&（而不是 Log）时，这被称为 **“返回引用（Return by Reference）”**。

- **返回引用 (Log&)**：函数返回的是内存中 **已存在对象的一个别名（Alias）**。调用者拿到的是那个对象本身，没有产生新的副本。
    
- **返回传值 (Log)**：函数会把内存里的对象 **复制（Copy）** 一份，把副本交给调用者。

>当你定义一个变量，或者在函数参数列表里看到 `&` 时，它表示**“别名”**。它不是取地址，也不产生新内存，只是给已有的变量起个外号。

- **特征**：紧跟着类型（如 `int&`、`float&`、`MyClass&`）。
    
- **位置**：通常在赋值号 `=` 的左边，或者函数的参数里。
    
```cpp
int a = 100;

// 【引用】
// 这里的 & 紧挨着类型 int，意思是 b 是 a 的“分身”
int& b = a; 

b = 200; // 修改 b 就是修改 a
// 此时 a 也变成了 200
```

**函数参数中的例子：**
```cpp
// 【引用】
// 这里的 & 表示 x 不是副本，就是调用者传进来的那个变量本身
void func(int& x) { 
    x++; 
}
```

---

### 2. 身份二：取地址（Address-Of）

**口诀：出现在“变量”旁边，就是取地址。**

当你想知道一个变量在内存里的门牌号（也就是指针指向的值）时，用这个。

- **特征**：前面没有类型，直接放在已经存在的变量名前面。
    
- **位置**：通常在赋值号 `=` 的右边。

```cpp
int a = 100;

// 【取地址】
// 这里的 & 放在变量 a 前面，意思是“获取 a 的内存地址”
// 结果必须存到一个指针（int*）里
int* p = &a; 

// 此时 p 的值可能是 0x7ffd8a...（一个十六进制的内存地址）
```

---
### 3. 身份三：按位与（Bitwise AND）

**口诀：夹在两个“数字/变量”中间，就是数学运算。**

这是逻辑运算，跟指针和引用都没关系。

- **特征**：左右两边都是东西（数字或变量）。
    
```cpp
int x = 5; // 二进制 101
int y = 3; // 二进制 011

// 【按位与】
// 夹在中间，做二进制运算：101 & 011 = 001
int z = x & y; 
```

---

### ⚡️ 终极分辨图解（一张图看懂）

请看这一行最令人迷惑的代码：
```cpp
int* p = &a;
```

我们要把它拆开看：

1. **左边 `int*`**：这是在定义**类型**，告诉编译器 `p` 是一个**指针**。
    
2. **右边 `&a`**：这是在做**动作**，表示**取出 `a` 的地址**。


```cpp
int& b = a;
```

1. **左边 `int&`**：这是在定义**类型**，告诉编译器 `b` 是一个**引用**。
    
2. **右边 `a`**：把 `a` 这个人绑在 `b` 这个名字上。
    

---

### 总结口诀（建议背诵）

| 代码长相     | 这里的 `&` 是什么？          | 含义               |
| -------- | --------------------- | ---------------- |
| `int& x` | **引用** (Reference)    | 定义一个别名。          |
| `&x`     | **取地址** (Address-Of)  | 获取变量的内存地址（给指针用）。 |
| `x & y`  | **按位与** (Bitwise AND) | 数学运算（二进制与）。      |
| `x && y` | **逻辑与** (Logical AND) | 逻辑判断（并且）。        |

**一句话心法：**  
**“左类引用，右变取址。”**  
（定义类型时在左边是引用，操作变量时在右边是取地址）




# 友元friend
`friend`（友元）是 C++ 中一个**打破封装**的关键字。
==友类，友类外函数，友类中函数==
它的作用非常霸道：**让一个外人，可以随意访问我私藏的“秘密”（即 `private` 和 `protected` 成员）。**

通常在面向对象编程（OOP）中，`private` 成员是绝对禁止外部访问的。但有时候为了方便（或者迫不得已），我们需要给某个“好朋友”开个后门，这就用到了 `friend`。

`friend` 主要有三种用法，按常用程度排序：

---
### 1. 友元函数 (Friend Function) —— 最常用

**场景**：你需要定义一个普通的全局函数（不是类的成员函数），但这个函数需要读取或修改某个类的私有数据。

**最经典案例：重载 `<<` (cout) 运算符**  
`std::cout` 是 C++ 标准库的东西，它不可能成为你自定义类的成员函数。所以，为了能写 `cout << myObj;`，你必须把这个运算符函数声明为“友元”。
==友元函数不属于类的成员，因此不能被声明为`const`。`const`限定符只能用于非静态成员函数。==
```cpp
#include <iostream>

class Box {
private:
    int secretValue = 999; // 私有数据，外人不可见

public:
    // 声明友元函数
    // 意思是：printBox 这个函数虽然不是我家人，但我允许它看我的秘密
    friend void printBox(Box& b);
};

// 这是一个普通的全局函数
void printBox(Box& b) {
    // 因为它是 friend，所以它可以直接访问 b.secretValue
    // 如果没有 friend，这行代码会报错！
    std::cout << "The secret is: " << b.secretValue << std::endl;
}

int main() {
    Box b;
    printBox(b); // 输出 999
    return 0;
}
```

---
### 2. 友元类 (Friend Class) —— 关系户

**场景**：你有两个类，关系非常紧密（比如 `Manager` 类需要管理 `Worker` 类的所有内部细节）。你想让类 B 的所有成员函数都能访问类 A 的私有成员。

**用法**：

- **单向的**：A 声明 B 是朋友，B 可以访问 A。但 A 不能访问 B（除非 B 也声明 A 是朋友）。
    
- **不传递**：朋友的朋友不是朋友。
    
```cpp
class Worker {
private:
    int salary = 5000;

    // 声明 Manager 是我的朋友
    // Manager 里的所有方法都可以访问我的 private
    friend class Manager; 
};

class Manager {
public:
    void adjustSalary(Worker& w, int newSalary) {
        // Manager 可以直接修改 Worker 的私有成员 salary
        w.salary = newSalary; 
    }
};
```

---

### 3. 友元成员函数 (Friend Member Function) —— 精确打击

**场景**：你只想让另一个类中的**某一个特定函数**成为朋友，而不是整个类。这是一种更精细的控制，但在 C++ 中写起来比较麻烦（涉及到前向声明和头文件顺序），所以用得比较少。

```cpp
class Worker; // 前向声明

class Manager {
public:
    void adjustSalary(Worker& w); // 先声明
};

class Worker {
private:
    int salary = 5000;
    
    // 只把 Manager::adjustSalary 这一特定函数当朋友
    friend void Manager::adjustSalary(Worker& w);
};
```

---

### ⚠️ 慎用 `friend`！

虽然 `friend` 很方便，但在 C++ 最佳实践中，**能不用尽量不用**。

**为什么？**

1. **破坏封装性**：OOP 的核心就是“隐藏细节”。`friend` 就像在墙上开了个洞，开得多了，墙就不存在了。
    
2. **耦合度过高**：一旦你修改了 A 类的私有成员名字，所有声明为 friend 的 B 类代码全都要改。

**什么时候该用？**

1. **运算符重载**（如 `operator<<`, `operator>>`）。
    
2. **单元测试**：测试代码需要验证类的私有状态时，可以把测试类设为 friend。
    
3. **紧密协作的类**：如链表节点（Node）和链表（List），Node 的私有数据只给 List 看。

**一句话总结：**  
`friend` 是给必须要看你隐私的“特权阶级”发的通行证，发的时候要慎重。

# C++ std::mutex
### 1. 本质 (What is it?)

- **互斥量 (Mutual Exclusion)**：一个“令牌”。
    
- **作用**：保护**临界区 (Critical Section)**，确保同一时间只有一个==线程==能访问共享资源（如全局变量、文件写入）。
    
- **特性**：**不可拷贝**（你不能复制一把锁，只能引用它）。
    
---
### 2. 原始操作 (Raw API)

_不推荐在现代 C++ 中直接裸写，容易写出 Bug。_
定义：std::mutex m;
- **`m.lock()`**：尝试拿锁。如果锁被别人拿着，当前线程**阻塞（睡觉等待）**。
    
- **`m.unlock()`**：释放锁。**必须**与 `lock()` 成对出现。
    
- **`m.try_lock()`**：尝试拿锁。
    
    - 拿到了 -> 返回 `true`。
        
    - 没拿到 -> 返回 `false`（**不阻塞**，直接向下执行）。
        

---

### 3. 智能管理 (RAII Wrappers) —— **核心考点**

_C++ 的黄金法则：利用对象生命周期自动管理锁，防止忘记 unlock 或异常导致死锁。_

| 类型                     | 特点                                       | 适用场景                                             |
| ---------------------- | ---------------------------------------- | ------------------------------------------------ |
| **`std::lock_guard`**  | **最轻量**。构造时锁，析构时解。**不可中途手动 unlock**。     | 90% 的简单场景（如保护一个变量自增）。                            |
| **`std::unique_lock`** | **灵活**。构造时锁，析构时解。**可以中途手动 unlock/lock**。 | 需要配合条件变量 (`condition_variable`) 使用，或锁的粒度需要精细控制时。 |
| **`std::scoped_lock`** | **C++17 神器**。可以同时锁住多个 mutex，**自动防死锁**。   | 需要同时锁住 `m1`, `m2`... 的场景。                        |

---

### 4. 死锁 (Deadlock)

- **成因**：
    
    1. **忘记解锁**：`lock()` 后发生异常或 `return`，没跑到 `unlock()`。 -> **解法：用 RAII (`lock_guard`)**。
        
    2. **顺序冲突 (ABBA)**：线程 A 锁 `m1->m2`，线程 B 锁 `m2->m1`。 -> **解法：保证加锁顺序一致**。
        
- **一行代码解决死锁 (C++17)**：
    
    cpp
    
    ```cpp
    // 自动按安全算法同时锁住 m1 和 m2
    std::scoped_lock lock(m1, m2); 
    ```
    

---

### 5. 性能原则 (Performance)

- **锁的粒度 (Granularity)**：
    
    - **锁太粗**（大锁）：把整个函数都锁住 -> 安全,但慢，变成了串行程序。
        
    - **锁太细**（小锁）：只锁那一行修改数据的代码 -> 并发度高，但逻辑复杂。
        
- **原则**：**临界区越小越好**。只在真正修改共享数据的那一瞬间加锁，耗时的操作（如 I/O、复杂计算）尽量移到锁外面。
    

---

### 6. 常见变种 (Variants)

- **`std::recursive_mutex` (递归锁)**：允许**同一个线程**多次 `lock` 同一把锁而不死锁。
    
    - _评价_：如果你需要用到它，通常说明你的代码设计有问题（函数调用层级太乱）。
        
- **`std::shared_mutex` (读写锁，C++17)**：
    
    - **读锁 (`shared_lock`)**：允许多个线程同时读（并发读）。
        
    - **写锁 (`unique_lock`)**：只允许一个线程写（独占）。
        
    - _适用_：**读多写少**的场景（如缓存系统）。

#### 2. 重载「二元运算符」（如 `+`、`-`、`==`）

以 `operator+` 为例，实现两个自定义对象的 “相加”：

```
class Point {
    int x, y;
public:
    Point(int x = 0, int y = 0) : x(x), y(y) {}

    // 成员函数形式：左操作数是当前对象（this）
    Point operator+(const Point& other) const {
        return Point(x + other.x, y + other.y);
    }

    // 全局函数形式（适合对称运算符，如 +、==）
    friend Point operator-(const Point& a, const Point& b) {
        return Point(a.x - b.x, a.y - b.y);
    }
};

// 使用示例
Point a(1, 2), b(3, 4);
Point c = a + b; // 等价于 a.operator+(b)
Point d = a - b; // 等价于 operator-(a, b)
```

#### 3. 重载「一元运算符」（如 `++`、`!`、`*`）

以自增运算符 `++` 为例，区分前置和后置：

```
class Counter {
    int count = 0;
public:
    // 前置 ++（返回引用，支持链式操作）
    Counter& operator++() {
        count++;
        return *this;
    }

    // 后置 ++（用 int 占位符区分，返回临时对象）
    Counter operator++(int) {
        Counter temp = *this;
        count++;
        return temp;
    }
};

// 使用示例
Counter c;
++c;   // 调用 operator++()
c++;   // 调用 operator++(int)
```

1. **看资源，不看代码**：看你的线程在争抢什么“东西”（变量、文件、外设）。
    
2. **抢同一个东西 -> 用同一个锁**：不管你有多少个函数，只要它们都动同一个变量，就得用同一把锁。
    
3. **抢不同的东西 -> 用不同的锁**：井水不犯河水，各自配各自的锁，实现最大并发。

### 1. STL 容器（最容易崩溃的地方）
这是 C++ 多线程崩溃的重灾区。标准库的容器（std::vector, std::map, std::queue, std::list 等）**都不是线程安全的**。

- **场景**：线程 A 往 vector 里 push_back 数据，线程 B 也在 push_back，或者线程 C 在读取数据。
- ==**后果**：==
    - **数据覆盖**：两个数据写到了同一个位置。
    - **Double Free**：内存被重复释放，程序直接崩溃。
    - **迭代器失效**：vector 扩容（Reallocate）时旧内存被释放，另一个线程手里拿着的地址瞬间变成野指针，一访问就崩溃。
- **解决**：必须有一个专门保护这个容器的锁。

### 2. 文件读写（日志系统）
这和 std::cout 的原理一模一样。

- **场景**：多个线程同时往同一个 log.txt 文件里写日志。
- **后果**：
    - **内容乱序**：A 线程写了一半“Error: Disk full”，B 线程插进来写“User Login”，最后文件里变成：“ErrUser Loginor: Disk full”。
    - **文件句柄损坏**：极其罕见，但可能导致文件无法关闭或数据丢失。
- **解决**：通常我们会封装一个 Logger 类，类里面有一个 mutex，写文件前先锁住。

### 3. 全局变量 / 静态变量
任何在 main 函数之外定义的变量，或者类里的 static 成员。

- **场景**：一个全局计数器 int g_count = 0;，多个线程同时执行 g_count++。
- **后果**：
    - **计数错误**：本来应该是 2000，结果跑出来是 1500。因为 ++ 操作不是原子的（它分读取、加1、写回三步，线程间会互相覆盖）。
- **解决**：
    - 方案 A：加锁。
    - 方案 B（推荐）：对于简单变量，使用 std::atomic\<int>，性能比锁快得多。

### 4. 数据库连接 / 网络套接字 (Socket)
- **场景**：你有一个 MySQL 连接对象 conn，线程 A 想用它查用户表，线程 B 想用它查订单表。
- **后果**：
    - **协议错乱**：A 发了一半的 SQL 语句，B 发了另一半。数据库收到的是一堆乱码，直接报错断开连接。
- **解决**：
    - 要么加锁，保证同一时间只有一个线程在用这个连接。
    - **更好的做法**：使用“连接池”，每个线程从池子里拿一个自己专属的连接，用完放回去（这样就不需要锁连接对象本身了）。

### 5. 第三方非线程安全库（Legacy Code）
很多老旧的 C 语言库（比如早期的 OpenSSL、某些图形驱动 OpenGL 上下文）内部有全局状态。

- **场景**：两个线程同时调用同一个库函数。
- **后果**：库内部的静态变量被改乱，导致不可预测的逻辑错误。
- **解决**：必须用一把“全局大锁”包住这个库的所有调用。

### 总结：如何判断“要不要加同一个锁”？
你可以问自己三个问题，如果答案都是 **YES**，就==必须加锁==：

1. **共享吗？** （这个变量/对象是不是被多个线程看见了？）
    
2. **可变吗？** （是不是至少有一个线程在**写**它？如果大家都是只读，那不需要锁。）
    
3. **非原子吗？** （这个操作是不是一步完不成的？比如 vector 扩容、printf 打印字符串。）

# Static 关键字
## 定义
`static`**不是**访问修饰符，它是 C++ 中的**存储类说明符（Storage Class Specifier）**，核心作用是修改变量、函数或类成员的**存储方式、生命周期、作用域 / 链接性**，而非控制 “能否被访问”（这是访问修饰符的职责）。
## 1.**在函数内部**（静态局部变量）
- **特点**：
    - **生命周期**：==贯穿整个程序运行期间==（直到程序结束）。
    - **作用域**：只能在该函数内部访问。
    - **初始化**：只在该代码**第一次被执行**时初始化一次。
        
- **用途**：
    - 用于**单例模式**（如你的代码）。
    - 用于**计数器**（统计函数被调用的次数）。
        
- **示例**：
    ```cpp
    void Counter() {
        static int count = 0; // 只在第一次调用时执行，且内存不销毁
        count++;
        std::cout << "调用次数: " << count << std::endl;
    }
    
    int main() {
        Counter(); // 输出: 1
        Counter(); // 输出: 2 (count 保留了上次的值)
        Counter(); // 输出: 3
    }
    ```
- **重要补充 (C++11 特性)**：  
    在 C++11 之后，静态局部变量的初始化是**线程安全**的（Thread-Safe）。这意味着如果多个线程同时第一次调用 GetInstance2，编译器会保证 static Log* b 只被初始化一次。这被称为 "Magic Static"。
---
## 2.**在类内部**（静态成员变量/函数）
当 static 用在类里面时，表示这个成员**属于类本身，而不是属于某个对象**。
#### A. 静态成员变量
- **含义**：所有该类的对象**共享同一个变量**。
    
- **存储**：不占用对象的内存（sizeof 不包含它），存储在全局数据区。
    
- **示例**：
    ```cpp
    class Player {
    public:
        static int online_count; // 声明：所有玩家共享这个计数器
    
        Player() { online_count++; }
        ~Player() { online_count--; }
    };
    
    // 必须在类外定义（分配内存）
    int Player::online_count = 0; 
    
    int main() {
        Player p1;
        Player p2;
        std::cout << Player::online_count; // 输出 2
    }
    ```
#### B. 静态成员函数

- **含义**：不需要创建对象就可以调用的函数。
	
- **限制**：
    
    - **没有 this 指针**。
        
    - 只能访问**静态**成员变量或其他**静态**成员函数（不能直接访问普通的 x, y 变量）。
        
- **你的代码示例**：  
    你的 GetInstance1() 和 GetInstance2() 都是 static 的。  
    这就是为什么你可以用 Log::GetInstance1() 直接调用，而不需要先 new 一个 Log 对象。
    
---
## 3.**在全局/文件作用域**（静态全局变量/函数）
当 static 写在所有函数外面（也就是 .cpp 文件顶层）时，它的含义变成了**控制链接性 (Linkage)**。

- **含义**：该变量/函数**只在这个 .cpp 文件内部可见**（Internal Linkage）。
    
- **用途**：**隐藏符号**，避免和其他 .cpp 文件中的同名变量冲突。
    
- **场景演示**：  
    假设你有两个文件：
    
    **File1.cpp**
    ```cpp
    int x = 10; // 全局变量，默认是 extern 的，其他文件也能看到
    ```
    
    **File2.cpp**
    ```cpp
    int x = 20; // 错误！链接器会报错：重定义符号 x
    ```
    
    **如果加上 static：**  
    **File1.cpp**
    ```cpp
    static int x = 10; // 这个 x 只属于 File1
    ```
    
    **File2.cpp**
    ```cpp
    static int x = 20; // 这个 x 只属于 File2，两者互不干扰
    ```
    > 注：在现代 C++ 中，为了达到这个目的，更推荐使用 **匿名命名空间 (Unnamed Namespace)**，效果是一样的。

# std::function
### 1.【官方/教科书定义】

**std::function** 是 C++11 标准库 \<functional> 头文件中引入的一个 **类模板（Class Template）**。它是一种 **通用多态函数封装器（General-Purpose Polymorphic Function Wrapper）**。

- **核心机制**：类型擦除（Type Erasure）**。它可以存储、复制和调用任何 **可调用对象（Callable Target）**，只要这些对象的参数和返回值符合 std::function 声明的签名即可。
    
- **支持的可调用对象包括**：
    
    1. 普通函数（Free Function）
        
    2. 函数指针（Function Pointer）
        
    3. 类成员函数指针（Member Function Pointer）
        
    4. 仿函数（Functor，即重载了 operator() 的类对象）
        
    5. **Lambda 表达式**（特别是带有捕获列表的 Lambda）
        
    6. std::bind 表达式的结果
        

### 2. 【通俗比喻解释】

std::function 就像是一个 “函数”的"**万能适配器容器**"（一个装不同函数的盒子）。

### 3.【简单易懂的代码示例】

这个例子展示了如何用 std::function 来“包装”一个普通的加法逻辑。

```cpp
#include <iostream>
#include <functional> // <--- 必须要有这个头文件

int main() {
    // 1. 声明：创建一个能“吃两个int，吐一个int”的通用函数容器
    //    格式：std::function<返回值(参数1, 参数2)>
    std::function<int(int, int)> myFunc;

    // 2. 赋值：我们要给这个容器装入一个具体的任务（这里用 Lambda 表达式）
    //    这里的 [](int a, int b) { ... } 就是一个 Lambda
    myFunc = [](int a, int b) -> int {
        return a + b;
    };

    // 3. 调用：像普通函数一样使用它
    int result = myFunc(10, 20);

    std::cout << "结果是: " << result << std::endl; // 输出 30

    return 0;
}
```

# 左右值引用
## 左右定义：
- **左值（Lvalue - 定位值）：**
    
    - 指**在内存中有明确存储地址、有名字**的变量或对象。
        
    - **特征**：你可以对它取地址（&a），它在当前行代码执行完后**依然存在**。
        
    - 例子：int a = 10; 中的 a。
        
- **右值（Rvalue - 读值）：**
    
    - 指**没有名字、无法取地址**的临时数据。通常是字面量（如 10）、运算表达式的结果（如 x + y）或函数的非引用返回值。
        
    - **特征**：它在当前行代码执行完后**立即销毁**（生命周期极短）。
        
    - 例子：int a = 10; 中的 10。
        
- **左值引用 (&)**：
    
    - 也就是我们常说的“引用”，是给**左值**起别名。
        
    - 语法：int& ref = a;（正确），int& ref = 10;（错误，不能给字面量起别名）。
        
- **右值引用 (&&)**：
    
    - C++11 新增特性。专门用来绑定到**右值**（临时对象）上的引用。
        
    - 语法：int&& ref = 10;（正确），int&& ref = a;（错误，a 是左值）。
- 函数参数中运用的简单区别
- ![](图片/C++/知识/IMG-20260214180915279.png)

## 定义与右引用的区别
- **普通定义 (Object Definition)**：
    
    - 例如 int a = 10; 或 string s = "hello";。
        
    - 这表示在栈（Stack）上**分配了一块新的内存**，然后把数据（10 或 "hello"）**拷贝**或**构造**进这块内存里。变量 a 拥有这块内存的**所有权**。
        
- **右值引用定义 (Rvalue Reference Declaration)**：
    
    - 例如 int&& b = 10;。
        
    - 这表示**不分配**用来存数据的新内存（概念上），而是创建一个**引用（别名）**，直接绑定到一个**本来马上就要销毁的临时对象（右值）** 上。
        
    - **核心机制 —— 生命周期延长 (Lifetime Extension)**：C++ 标准规定，当一个右值引用绑定到一个临时对象时，这个临时对象的生命周期会被延长，直到这个引用变量离开作用域为止。
- **本质区别**：
	- **普通定义** = **克隆/新建**（我买了一个新手机）。
    
	- **右值引用** = **续命/接盘**（我捡了一个别人刚要扔掉的手机，暂时归我用）。

## 左右值参数的矛盾
### 1.左值引用传入的是右值(需要传变量)
- **非 const 左值引用 (T&)**：
    
    - **不能** 绑定到右值（临时对象）。
        
    - **后果**：编译器直接**报错**（Compile Error）。
        
    - 原因：非 const 引用暗示函数内部可能会**修改**传入的参数。修改一个即将销毁的临时对象（右值）通常是没有意义的逻辑错误，所以 C++ 禁止这样做。
        
- **const 左值引用 (const T&)**：
    
    - **可以** 绑定到右值。
        
    - **后果**：编译通过，且会触发 **生命周期延长（Lifetime Extension）**。
        
    - 原因：const 承诺了“我只读不改”。既然不修改，读取一个临时对象的数据是安全的。
### 2.右值引用传入左值(需要传常值)
- **绑定规则**：
    
    - **右值引用 (T&&)**：只能接临时对象（如字面量 10、x + y 的结果、std::move(x) 的返回值）。
        
    - **左值 (T 或 T&)**：是具名的、持久的对象。
- 实在需要传入，需要用std::move()

# std::forward(转发)
**std::forward** 是 C++ 标准库 \<utility> 中的一个函数模板。它的核心作用是实现 **完美转发（Perfect Forwarding）**。

- **定义**：它将参数的 **值类别（Value Category）**（即左值还是右值）**原封不动**地保留并传递给下一个函数。(==优化性能，拷贝==)
    Lambda是右值
- **机制**：
    
    - 如果传递给外层函数的是 **左值**，std::forward 就把参数当做 **左值** 传给内层函数（引发拷贝）。
        
    - 如果传递给外层函数的是 **右值**，std::forward 就把参数当做 **右值** 传给内层函数（允许移动）。
        
- **适用场景**：任何使用了 **万能引用（Universal Reference, T&&）** 的模板函数中。

# Template 模板
### 1. 【官方/教科书定义】

**模板 (Template)** 是 C++ 支持 **泛型编程 (Generic Programming)** 的核心机制。

- **本质**：它不是真正的代码，而是**生成代码的蓝图 (Blueprint)** 或 **配方 (Recipe)**。
    
- **机制**：编译器在**编译期 (Compile-time)** 根据用户指定的具体类型（如 int, float, MyClass），利用模板自动生成具体的函数或类代码。这个过程称为 **模板实例化 (Template Instantiation)**。
    
- **多态性**：模板提供了 **编译期多态 (Static Polymorphism)**，与虚函数提供的运行期多态相对。
    

---

### 2. 【通俗比喻解释】

**模板 = 月饼模具 / 印章**

- **普通函数/类**：就像是 **手工捏出来的一个具体的月饼**（比如豆沙馅的）。如果你想要莲蓉馅的，你得重新捏一个。
    
- **模板**：就像是 **一个木制的月饼模具**。
    
    - 模具本身不能吃（模板不能直接运行）。
        
    - 你往模具里填 **“int 馅”**，按一下，就出来一个处理整数的函数。
        
    - 你往模具里填 **“double 馅”**，按一下，就出来一个处理浮点数的函数。
        
    - **特化 (Specialization)**：就像是针对“五仁馅”这种特殊的材料，普通的模具压不动，你需要专门定制一个**特殊的模具**来处理它。
        

---

### 3. 【扩展与实战应用：知识图谱】

我将模板知识分为 **基础、进阶、高阶、黑魔法** 四个层级，带你彻底打通。

#### 第一层：基础语法 (The Basics)

**1. 函数模板（函数模板）**  
不需要为 int、float、long 分别写 swap 函数。
"==使用函数时，在函数名后面+<>=="
```cpp
template <typename T> // T 是个占位符，以后填什么都行
void mySwap(T& a, T& b) {
    T temp = a;
    a = b;
    b = temp;
}
// 调用：mySwap<int>(a, b); 或自动推导 mySwap(a, b);
```

**2. 类模板（类模板）**  
STL 容器（vector, list）的原理。
"==声明类时，在类名后面+<>=="
```
template <typename T>
class Box {
private:
    T content;
public:
    void set(const T& val) { content = val; }
    T get() { return content; }
};
// 使用：Box<int> intBox; Box<string> strBox;
```

---

#### 第二层：参数与特化 (Intermediate)

**1. 非类型模板参数 (Non-type Template Parameters)**  
模板不仅可以传“类型”，还可以传“数值”。这在嵌入式或矩阵库中非常重要。
//额外添加<>内参数，直接使用
```cpp
// N 是编译期常量，必须是整数、指针或引用
template <typename T, int N>
class Array {
    T data[N]; // 编译期确定数组大小，分配在栈上，速度极快
};
// 使用：Array<int, 5> arr; // 类似于 std::array
```

**2. 模板特化（专精）**  
“特殊情况特殊处理”。

- **全特化 (Full Specialization)**：针对某个具体类型（如 bool）完全重写逻辑。
  
    ```cpp
    // 通用版本
    template <typename T> struct Equal { ... }; 
    
    // 针对 float 的特化（处理浮点误差）
    template <> 
    struct Equal<float> { 
        static bool is(float a, float b) { return abs(a - b) < 1e-5; } 
    };
    ```
    
- **偏特化 (Partial Specialization)**：只限制部分参数，或者限制参数的类别（如指针）。
    
    - 注意：函数模板不能偏特化，只有类模板可以。

#### 第三层：现代 C++ 高阶特性 (Modern C++)

**1. 变参模板 （Variadic Templates） （C++11）** (C++11)  
就是你刚才问的 template<typename... Args>。用于实现 printf、std::tuple、线程池等需要任意数量参数的场景。

**2. 折叠表达式（折叠表达式）（C++17）** (C++17)  
简化变参模板的递归写法。
//。。。
```cpp
template<typename... Args>
auto sum(Args... args) {
    return (... + args); // 极其优雅的求和
}
```

**3. 概念 (Concepts)** (C++20) **[重要趋势]**  
解决了模板报错“天书”的问题。它允许你限制 T 必须满足什么条件。

```
template <typename T>
requires std::integral<T> // 限制 T 必须是整数
T add(T a, T b) { return a + b; }
```

---

#### 第四层：模板元编程 (Template Metaprogramming - TMP)

这是 C++ 最晦涩但也最强大的领域：**利用模板在编译期进行计算**。

**1. 编译期计算**  
在程序运行之前，结果已经算好了。

```cpp
template<int N>
struct Factorial {
    static const int value = N * Factorial<N - 1>::value;
};
template<>
struct Factorial<0> {
    static const int value = 1;
};
// int x = Factorial<5>::value; // 编译器直接把这行代码替换为 120
```

**2. SFINAE（替换失败不是错误）**  
**“替换失败不是错误”**。这是 C++ 模板推导的核心规则。

- **解释**：编译器尝试把类型填进模板时，如果发现填进去导致代码不合法（比如类型没有 size() 成员函数），它不会直接报错，而是默默地**忽略**这个模板，去试下一个。
    
- **用途**：用于在编译期检测一个类有没有某个方法，从而决定调用哪个版本的函数（std::enable_if 的原理）。

#### 岗位与实战应用

**1. 基础库/SDK 开发工程师 (Qt/Boost/STL)**

- **工作内容**：你写的代码会被成千上万的开发者使用，必须支持 int、double、UserClass 等各种类型。
    
- **要求**：必须精通模板，避免代码膨胀，保证通用性。
    

**2. 高性能计算 / 游戏引擎 (HPC / Game Engine)**

- **性能优化**：利用模板将计算从 **运行时 (Runtime)** 移到 **编译时 (Compile-time)**。
    
    - 例如矩阵运算库 Eigen，利用模板表达式模板 (Expression Templates) 消除临时对象，实现极致性能。
        
- **策略模式优化**：用 Policy Based Design（基于策略的设计）代替虚函数继承，消除虚函数调用的开销。
    

**3. 嵌入式开发**

- **资源限制**：使用 std::array (模板封装) 代替 std::vector，因为模板可以在栈上分配内存，避免堆分配（malloc）带来的碎片和时间不确定性。
    

**总结建议：**

- **初学者**：会写 template\<typename T> 的函数和类即可。
    
-  **中级**：理解特化、非类型参数，能看懂 vector 的源码。
    
- **高级**：掌握变参模板、SFINAE、Concepts，能写出像 std::function 或 ThreadPool 这样的通用组件。

# Lambda 函数
### 1. 【官方/教科书定义】

**Lambda 表达式 (Lambda Expression)** 是 C++11 引入的一种用于定义 **匿名函数对象 (Anonymous Function Object)** 的语法糖。

- **本质**：它不是一个普通的函数，编译器在编译时会把它转化为一个 **未命名的类（Closure Type，闭包类型）**。
    
- **闭包 (Closure)**：这个类重载了 operator()，因此它可以像函数一样被调用。它还可以包含成员变量（由捕获列表生成），从而携带状态。
    
- **完整语法**：  
    [捕获列表](参数列表) mutable exception -> 返回类型 { 函数体 }
    

### 2. 【通俗比喻解释】

**Lambda = “一次性外卖员” + “他的外卖箱”**

- **普通函数**：像是 **有编制的厨师**。
    
    - 他有固定的名字（函数名），固定的工位（作用域）。
        
    - 你想让他干活，得去厨房找他。
        
    - 他只能用厨房里的东西，或者是你传给他的食材（参数）。
        
- **Lambda**：像是 **临时雇佣的外卖员**。
    
    - **匿名**：他没有名字，随叫随到，干完活就消失（除非你用 std::function 把他留下来）。
        
    - **捕获列表 []（外卖箱）**：这是 Lambda 最强大的地方。他可以把出发地（定义处）的东西打包带走。
        
        - [=]：把店里的菜单复印一份带走（只读）。
            
        - [&]：拿根绳子拴住店里的锅（引用）。
            
        - [this]：带上店里的万能钥匙（类成员访问权限）。
            
    - **参数列表 ()（订单）**：客户（调用者）给他的具体指令。
        

---

### 3. 【扩展与实战应用：解剖 Lambda】

为了彻底掌握它，我们需要拆解它的每一个零件，并结合实际工作场景。

#### A. Lambda 的解剖图

```cpp
[capture] (params) mutable -> ret { body }
```

1. **[capture] 捕获列表**：**（最关键！）**
    
    - **[]**：空手套白狼，不抓任何外部变量。
        
    - **[x, &y]**：x 按值捕获（复制），y 按引用捕获（原件）。
        
    - **[=]**：**全部按值捕获**。把外部所有可见变量都==复制==一份（慎用，可能复制大对象）。
        
    - **[&]**：**全部按引用捕获**。把外部所有变量都当原件用（慎用，小心悬空引用）。
        
    - **[this]**：捕获当前类对象的指针（访问成员变量用）。
        
2. **(params) 参数列表**：
    
    - 和普通函数一样。C++14 开始支持 auto（泛型 Lambda），例如 [](auto a, auto b) { return a+b; }。
        
3. **mutable 关键字**：**（面试考点）**
    
    - 默认情况下，[=] 捕获的变量在 Lambda 内部是 **const（只读）** 的。
        
    - 如果你想修改那个“副本”，必须加上 mutable。
        
4. **-> ret 返回类型**：
    
    - 通常可以省略，编译器会自动推导。
        

---

#### B. 编译器眼里的 Lambda（底层原理）

你写的是：

```cpp
int a = 10;
auto f = [a](int x) { return a + x; };
```

编译器生成的是（伪代码）：

```cpp
class __AnonymousLambdaName {
private:
    int a; // 捕获列表变成了成员变量
public:
    __AnonymousLambdaName(int _a) : a(_a) {} // 构造函数

    // 重载了 () 操作符，所以能像函数一样调用
    int operator()(int x) const { 
        return a + x; 
    }
};
```

**这就是为什么说 Lambda 本质是类对象。**

---

#### C. 工作中的具体运用场景

**场景 1：STL 算法（最经典用法）**  
以前为了自定义排序，还得专门写个函数或仿函数类，很麻烦。

```cpp
std::vector<int> v = {1, 5, 3, 4, 2};

// 需求：按降序排列
// 旧写法：需要定义一个 bool compare(int a, int b) ...
// Lambda 写法：原地定义逻辑
std::sort(v.begin(), v.end(), [](int a, int b) {
    return a > b; // 降序逻辑
});
```

**场景 2：智能指针的自定义删除器（资源管理）**  
在处理 C 语言遗留接口（如 FILE*、socket）时非常有用。

```cpp
// 打开一个文件
FILE* fp = fopen("test.txt", "w");

// 使用 unique_ptr 管理它，但 unique_ptr 默认用 delete，而 FILE* 需要 fclose
// 这里用 Lambda 指定怎么“删”这个指针
std::unique_ptr<FILE, void(*)(FILE*)> filePtr(fp, [](FILE* f) {
    fclose(f); // 当 filePtr 销毁时，自动调用 fclose
    std::cout << "文件已安全关闭" << std::endl;
});
```

**场景 3：IIFE (立即调用函数表达式) —— 复杂初始化**  
如果你有一个常量 const 需要初始化，但初始化逻辑很复杂（比如带 if-else），怎么写？

```cpp
// 这种写法很丑，因为 x 不能是 const，而且污染了作用域
int x;
if (condition) x = 10;
else x = 20;

// Lambda 写法：干净、安全、const
const int y = []() {
    if (condition) return 10;
    else return 20;
}(); // 注意最后这个 ()，表示定义完立马运行！
```

**场景 4：C++14 的移动捕获（性能优化）**  
如果外部有一个 **不可拷贝** 的对象（如 unique_ptr），你想把它移进 Lambda 里怎么办？  
C++11 做不到，C++14 可以：

```cpp
std::unique_ptr<int> ptr = std::make_unique<int>(100);

// [p = std::move(ptr)] 创建一个新的捕获变量 p，由 ptr 移动而来
auto task = [p = std::move(ptr)]() {
    std::cout << "指针里的值: " << *p << std::endl;
};

// 此时外面的 ptr 已经空了，所有权在 task 里面
```

**场景 5：回调函数与事件响应（GUI/网络）**  
这就是你线程池代码里的用法。

```cpp
// 按钮点击事件
button.onClick([this]() {
    this->refreshUI(); // 访问类成员
    this->logger.log("Button Clicked");
});
```

### 总结

1. **Lambda 是对象**，不是裸函数指针。
    
2. **[] 是数据**（成员变量），**() 是接口**（函数参数）。
    
3. **尽量捕获具体的变量**（如 [this, &a]），避免滥用 [=] 或 [&]，以防止意外的性能开销或悬空引用。


# std::async和std::future
头文件：\<future>
### 【官方/教科书定义】

- **std::async (Asynchronous Function)**：==创建后台线程，返回std::future对象==
    
    - 是一个**函数模板**，用于启动一个**异步任务**。
        
    - 它会自动创建一个新的线程（或复用线程池），在后台执行你指定的函数。
        
    - **返回值**：它返回一个 std::future 对象，该对象持有异步任务将来会产生的结果。
        
    - **本质**：它是对 std::thread 的高级封装，帮你管理了线程创建、生命周期以及返回值的传递。
        
- **std::future (Future Result)**：==线程运行结束后返回的对象==
    
    - 是一个**类模板**，代表一个 **“未来才会有的结果”**。
        
    - 它充当了 **主线程** 和 **后台线程** 之间的 **数据通道**。
        
    - **机制**：后台线程计算完结果后，会将结果放入 std::future；主线程在需要的时候，通过调用 future.get() 来获取这个结果。如果结果还没算出来，主线程会**阻塞等待**。
        

---

### 2. 【通俗比喻解释】

想象你去 **星巴克点咖啡**：

1. **std::async（点单并开始做）**：  
    你走到柜台点了一杯拿铁。店员收了钱，转头告诉咖啡师：“做一杯拿铁！”（启动后台任务）。
    
2. **std::future（取餐小票）**：  
    店员给了你一张 **小票**。
    
    - 这张小票 **不是咖啡**，但它 **代表了未来的咖啡**。
        
    - 你手里拿着小票，不需要站在柜台傻等，你可以去旁边找座位、玩手机、回消息（主线程做其他事）。
        
3. **future.get()（凭票取餐）**：  
    过了一会儿，你玩腻了手机，拿着小票去柜台要咖啡。
    
    - **情况 A**：咖啡已经做好了，店员立马给你（非阻塞，直接获取）。
        
    - **情况 B**：咖啡还没做好，你必须站在柜台前 **死等**，直到做好了给你（阻塞等待）。
        

**总结**：std::async 是“下单”，std::future 是“小票”。

### 3. 【扩展与实战应用】

#### 为什么要用它们？（对比 std::thread）

如果你用原始的 std::thread 来获取返回值，非常麻烦：

- **Thread 写法**：你需要定义一个全局变量或引用，加一把锁（Mutex），再加一个条件变量（Condition Variable）来通知主线程“算好了”。代码量大且容易写错。
    
- **Async/Future 写法**：两行代码搞定，自动处理锁和通知，还能传递异常。
    

#### 代码实战：简单的异步计算

```cpp
#include <iostream>
#include <future>
#include <thread>
#include <chrono>

// 一个耗时的计算任务（比如要去数据库查数据）
int heavy_calculation(int x) {
    std::this_thread::sleep_for(std::chrono::seconds(2)); // 假装算很久
    return x * x;
}

int main() {
    // 1. 启动异步任务
    // std::launch::async 强制创建一个新线程
    // 类似于：拿着小票去旁边玩
    std::future<int> ticket = std::async(std::launch::async, heavy_calculation, 10);

    std::cout << "主线程正在做其他事情..." << std::endl;
    std::this_thread::sleep_for(std::chrono::seconds(1));

    // 2. 获取结果
    // 类似于：拿着小票去换咖啡
    // 如果 heavy_calculation 还没跑完，这里会卡住等待
    int result = ticket.get(); 

    std::cout << "计算结果: " << result << std::endl;

    return 0;
}
```

#### 关键知识点

1. **std::launch 策略**：==在第一个参数位置（必填）==
    
    - ✅ std::launch::async：**强制**开启新线程执行（真正的并发）。
        
    - std::launch::deferred：**延迟执行**。任务不会立刻跑，直到你调用 .get() 时，才会在当前线程（主线程）里跑。这其实不是并发，而是“懒加载”。
        
    - 如果不写策略，编译器会根据系统负载自己看着办（这有时候是个坑）。
        
2. **只能 get() 一次**：==单次性==
    
    - std::future 是一次性的。一旦你调用了 .get()，结果就被移动（Move）出来了，小票就作废了。
        
    - 再次调用会抛异常。如果需要多个线程都要这个结果，得用 std::shared_future。

# const
**`const`放在函数参数列表`()`后面，是 C++ 中专门修饰「成员函数」的语法；而`const`放在函数开头，是修饰函数的「返回值」**，这是两种完全不同的用法。

### 1. `const` 放在 `()` 后面（成员函数的 `const` 限定）
==任何对象成员变量不改变==
这是你代码里看到的写法（如 `int getValue() const`），它有两个核心特点：

- **仅适用于类的非静态成员函数**：普通函数、友元函数、静态成员函数都不能用这种写法（这也是你代码中④非法的原因之一）。
- **核心作用**：承诺这个成员函数「不会修改当前对象的任何非`mutable`成员变量」，同时函数内的`this`指针会被视为`const 类名*`类型（即不能通过`this`修改对象）。

举个合法的例子：

```cpp
class AA {
    int a;
public:
    // 合法：仅读取a，不修改对象状态
    int getValue() const { 
        return a; // 只读操作，符合const承诺
    }

    // 非法：试图修改成员变量，违反const承诺
    void set(int n) const {
        a = n; // 编译报错：const成员函数不能修改非mutable成员
    }
};
```

### 2. `const` 放在函数开头（修饰返回值）
==返回值不变==
这种写法是修饰函数返回值的类型，和成员函数无关，普通函数也能用。

- 如果返回值是基础类型（如`int`）：`const int func()` 几乎无意义（因为返回值是拷贝，修改拷贝不影响原数据）。
- 如果返回值是指针 / 引用：`const int* func()` 表示返回的指针指向「不可修改的 int」，`const int& func()` 表示返回「不可修改的 int 引用」。

举个例子：

```cpp
class AA {
    int a = 10;
public:
    // const修饰返回值：返回的指针指向const int，不能通过该指针修改a
    const int* getRef() const { 
        return &a; // 此时this是const AA*，&a是const int*，类型匹配
    }
};

int main() {
    AA aa;
    const int* p = aa.getRef();
    // *p = 20; // 编译报错：p指向const int，不能修改
    return 0;
}
```

### 3. 两者的核心区别对比

| 写法位置                      | 作用对象      | 核心含义                         | 适用场景                  |
| ------------------------- | --------- | ---------------------------- | --------------------- |
| `()` 后面（如`func() const`）  | 类的非静态成员函数 | 函数不会修改当前对象的状态（`this`是 const） | 只读成员函数（如取值函数）         |
| 函数开头（如`const int func()`） | 函数返回值     | 返回值是 const 类型（不可修改）          | 限制返回值的修改（指针 / 引用场景有用） |

### 补充：容易混淆的其他写法

为了帮你彻底理清，再补充两种常见写法：

```cpp
class AA {
    int a;
public:
    // 1. const修饰参数（参数列表内）
    void func(const int n) { // n是const，函数内不能修改n
        // n = 10; // 报错
    }

    // 2. 组合写法：const修饰返回值 + const修饰成员函数
    const int& getA() const { // 返回const引用，且函数不修改对象
        return a;
    }
};
```

### 总结

1. `()` 后的`const`是**成员函数专属**，用来保证函数「不修改对象」，这是 C++ 封装和常量正确性的核心语法；
2. 函数开头的`const`仅修饰**返回值**，对基础类型返回值几乎无意义，主要用于指针 / 引用返回值；
3. 你代码中①的错误本质是：`()`后 const 让`&a`变成`const int*`，但返回值声明为`int*`，类型不匹配（而非`const`位置放错）。

# RAII（资源获取即初始化）
RAII 的全称是 **Resource Acquisition Is Initialization**（资源获取即初始化），核心思想可以用一句话概括：

**把资源的生命周期和对象的生命周期绑定在一起** —— 创建对象时 “自动获取” 资源，对象销毁时（比如离开作用域、析构函数调用）“自动释放” 资源，全程不需要手动调用释放函数。
