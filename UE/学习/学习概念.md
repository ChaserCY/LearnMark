# 1.游戏实例（GameInstance）：
|类 (Class)|生命周期 (存活时间)|适用场景|比喻|
|**GameMode**|**仅当前关卡**。<br>换地图就销毁。|关卡的规则（如：限时5分钟，胜利条件）。|房间里的裁判。|
|**PlayerController**|**仅当前关卡**。<br>换地图通常会重建。|玩家的输入控制、HUD显示。|你的手柄/键盘。|
|**SaveGame**|**永久（硬盘）**。<br>关机也不丢。|写文件到硬盘，用于存档。|你的日记本/硬盘。|
|**GameInstance**|**整个游戏运行期间**。<br>换地图不丢，关游戏才丢。|**跨关卡传数据**（内存中）。|**你的背包/大脑记忆。**|

**注意区分 SaveGame 和 GameInstance：**
- **GameInstance** 是存在**内存（RAM）** 里的。游戏关掉，数据就没了。
- **SaveGame** 是存在**硬盘**里的。
- **通常做法**：游戏运行时，把数据存在 GameInstance 里方便随时读写；当玩家到达存档点或退出游戏时，把 GameInstance 里的数据保存到 SaveGame（硬盘）里。

# 2.宏和函数
- **函数 (Function)** 就像是**“查字典”**。==引用==
    - 全班同学共用这一本字典。当你需要查一个字时，你跑去翻那本字典，查完了再回到座位上继续写作业。
        
- **宏 (Macro)** 就像是**“复印机/复制粘贴一整坨/复合节点”**。==复制==
    - 当你使用宏时，引擎会在编译时把宏里面的所有节点群，**原封不动地复制粘贴**到你放置宏的位置。
使用：函数用于输入输出计算(计算和结果)，宏用于封装整个逻辑群体(执行)
区别：
 1. 能否使用“潜流节点” (Latent Nodes) —— 最核心的区别
 2. 执行流（Execution Pins）的自由度
 ——宏：非常自由       函数：只能一个输入一个输出（一天执行流）
 3. 底层原理与性能 (Call vs Copy)
 ——函数：省内存，修改方便，速度快      宏：复制的开销大，体积膨胀
4.  作用域与通配符 (Scope & Wildcards)
——函数：静态，都可以调用           宏：指定父类，只能是这个父类子类才可以用，支持通配符IsValid检查

# 3.蓝图枚举

# 整数转枚举，Select(选择)节点
### 1. 枚举（Enum）有什么作用？

枚举的核心作用是**为了让逻辑更清晰、更易读，并防止出错**。

- **命名状态（可读性）：**
    
    - **不用枚举：** 假设你要做一个门的开关逻辑。你可v

- 能会用整数（Integer）变量：0 代表关，1 代表开，2 代表锁住。过两个月你再看代码，你可能会忘 2 到底是什么意思。
        
    - **用枚举：** 你创建一个枚举叫 E_DoorState，里面有 Open、Closed、Locked。在蓝图中，你看到的不再是数字，而是直接写着 Locked 的选项。
        
- **控制流程（Switch on Enum）：**
    
    - 这是枚举最强大的地方。你可以使用 **"Switch on [枚举名]"** 节点。这个节点会自动分叉出所有定义好的状态（如开、关、锁）。这比写一堆 Branch (If) 节点要整洁得多。
        
- **限制选项（安全性）：**
    
    - 当你在蓝图中公开一个变量给别人（或自己在编辑器细节面板）调节时，如果是整数变量，你可以输入 9999，这可能会导致程序崩溃。但如果是枚举变量，你只能从下拉菜单里选你定义好的那几个选项，绝对不会选错。
        

---

### 2. 枚举与普通变量（如 Int, Float, Boolean）有什么区别？

本质上，枚举在计算机底层**就是整数（Byte/Integer）**（第1个选项是0，第2个是1，以此类推），但在使用体验上有巨大区别：

|   |   |   |
|---|---|---|
|特性|普通变量 (Integer/Boolean)|枚举 (Enum)|
|**值的范围**|开放的。例如整数可以是 -20亿 到 +20亿。|**封闭的**。只能是你预先定义好的那几个选项。|
|**表现形式**|数字或勾选框。|**下拉列表（Dropdown List）**。|
|**语义**|只有数值，没有名字（除非你注释）。|**有明确的名字**（如 Idle, Run, Jump）。|
|**逻辑分支**|需要比较（Does A == 1?）。|直接分流（Switch on...）。|

---

### 3. 它是不是算一个“全部蓝图可直接用的设置对应蓝图对象的变量”？

这里需要纠正一个概念，你的理解**对了一半**。

**它的定义是全局的，但它的值是局部的。**

让我们拆解一下这个概念：

#### A. “全局定义” (Global Definition) —— 是的

当你创建一个枚举资产（在内容浏览器右键 -> Blueprints -> Enumeration）时，这个**枚举类型（Type）** 就变成了整个项目通用的。

- 你可以在**角色蓝图**里用这个枚举。
    
- 你可以在**UI蓝图**里用这个枚举。
    
- 你可以在**关卡蓝图**里用这个枚举。
    
- **大家都能“看见”并使用这个下拉菜单的结构。**
    

#### B. “全局变量” (Global Variable) —— 不是

这**并不**意味着你在一个蓝图里把枚举选成“A”，全世界所有蓝图里的这个枚举都会变成“A”。

- **举例：**
    
    - 你定义了一个枚举 E_Team（红队、蓝队）。
        
    - 你创建了 **10个** 小兵蓝图，每个小兵都有一个 E_Team 类型的变量。
        
    - 你可以把小兵A设为“红队”，把小兵B设为“蓝队”。
        
    - **它们互不干扰。**
        

**总结你的疑问：**  
枚举本身是一个**“模板”或“类型”**（就像 Integer 是一种类型），一旦创建，所有蓝图都可以创建这种类型的变量。但每个蓝图实例里存的具体是哪一个选项，是各自独立的。

---

### 一个实际应用的例子（武器系统）

假设你正在做射击游戏：

1. **创建枚举资产：** 在内容浏览器新建枚举 E_WeaponType，添加三个选项：Pistol（手枪）、Rifle（步枪）、Sniper（狙击枪）。
    
2. **在蓝图中使用：**
    
    - 打开你的角色蓝图。
        
    - 新建一个变量 CurrentWeapon，把变量类型选为 E_WeaponType。
        
    - 现在这个变量就是一个下拉菜单。
        
3. **编写逻辑：**
    
    - 拖入 CurrentWeapon 变量，连接一个 **Switch on E_WeaponType** 节点。
        
    - 这个节点会有三个输出引脚：Pistol、Rifle、Sniper。
        
    - 你可以连接不同的逻辑：手枪连“播放手枪音效”，狙击枪连“播放狙击音效”。

# 4.蓝图接口(信号通知)
与事件分发器的区别
![](图片/UE/学习/学习概念/IMG-20260324174142429.png)
### 1. 怎么用？（简易步骤）

使用接口分三步走：**创建 -> 领养（实现） -> 调用**。

#### **第一步：创建接口（定义协议）**

1. 在内容浏览器右键 -> **Blueprints** -> **Blueprint Interface**。
    
2. 命名为 BPI_Interaction（交互接口）。一
    
3. 打开它，在右侧添加一个函数，比如叫 OnInteract（被交互时）。你可以在这里加参数（Inputs），比如“是谁按的E键”。还有输入的参数或者变量

4. 编译，关闭。  
    注意：这里只写函数名字，**不写**具体逻辑。
    

#### **第二步：领养接口（在目标蓝图中实现，谁来继承接口）** 启用接口函数开始事件，然后编写逻辑

假设你有 **门（BP_Door）** 和 **灯（BP_Light）**。

1. 打开 **BP_Door**。
    
2. 点击上方工具栏的 **Class Settings（类设置）**。
    
3. 在右侧细节面板的 **Interfaces** 栏，点击 **Add**，搜索并选中 BPI_Interaction。
    
4. 编译。
    
5. 在左侧 **My Blueprint** 面板的 **Interfaces** 下，==双击== OnInteract（或者右键 -> Implement Function）。
    
6. **写逻辑：** 连线 Timeline 或 Set Rotation 让门打开。
    
7. (同样的步骤去 **BP_Light** 里做一遍，逻辑写成“开关灯”)。
    

#### **第三步：调用接口（在发送者蓝图中）**，传入相关参数，指定目标对象(==必须是领养接口类，或者其子类==)

假设是 **玩家（BP_Character）** 按下 E 键。

1. 使用射线检测（Line Trace）找到前方的物体，得到 Hit Actor。
    
2. 从 Hit Actor 引脚拉出来，搜索 **OnInteract (Message)**。
    
    - **关键点：** 一定要选右上角带有个==**小信封图标**==的那个（Message），不要选普通的函数调用。
        
3. 这就完了。
    

**结果：** 对着门按E，门开了；对着灯按E，灯亮了；对着墙按E，无事发生。

---
### 2.应用场景
蓝图接口在以下场景是**必用**的：

#### **A. 交互系统（Interaction System）**
这是最经典的的用法。

- **场景：** 玩家对着物体按“F”键。
    
- **对象：** 门（开门）、椅子（坐下）、NPC（对话）、武器（捡起）、电梯（按钮）。
    
- **做法：** 统一用接口 BPI_Interact。
    

#### **B. 伤害系统（Damage System）**
- **场景：** 爆炸或子弹击中物体。
    
- **对象：** 敌人（扣血）、玻璃（破碎）、队友（友伤提示）、无敌的墙（冒火花）。
    
- **做法：** 统一用接口 BPI_Damage。
    

#### **C. 物品栏/UI通信**
- **场景：** 你的背包里有把枪，有瓶水，有本书。
    
- **做法：** 当你在UI上点击“使用”时，UI并不知道这个物品是什么类。它只发送一个 UseItem 的接口消息。
    
    - 枪实现了接口 -> 装备。
        
    - 水实现了接口 -> 回血。
        
    - 书实现了接口 -> 显示文本。
        

### 总结
- **普通变量/函数：** 是你自己跟自己说话。
    
- **Cast To（类型转换）：** 是你指名道姓跟某人说话（如果那人不在，你就崩了）。
    
- **蓝图接口：** 是你拿个大喇叭喊话。谁听得懂谁就去做，听不懂的就当没听见。
    

**记住一句话：只要你想让两个毫无关系的蓝图进行互动，首选蓝图接口。**


# 5.音频
## 总结与对比表
导入wav源文件，然后创建Cue，随后给Cue归类，在Cue中绑定Class，统一管理
UE 音频体系的核心是：**Sound Wave（原始音频）→ Sound Cue / MetaSound（逻辑 / 处理）→ Sound Class / Bus（分组混音）→ Audio Component（场景播放）**，从 “素材” 到 “逻辑” 再到 “控制” 和 “场景实例” 逐层向上。

## 一、核心音频资产（最基础）

### 1. Sound Wave（声波 / 原始音频）

- **定义**：导入引擎的**原始音频文件**（WAV/OGG 等），是最底层的音频数据载体。
- **作用**：存储**单段音频波形数据**（如单次脚步声、枪声）。
- **特点**：
    
    - 无逻辑、无分支、无动态变化
    - 仅含基础属性：音量、音调、循环、压缩设置
    
- **类比**：**原材料（一块铁）**

### 2. Sound Cue（声音线索 / 音效逻辑）

- **定义**：**节点图式音频逻辑资产**，用于组合、处理、控制 Sound WaveEpic Games。
- **作用**：
    
    - 拼接多段音频、随机播放、循环、交叉淡化
    - 添加音量 / 音调随机、延迟、混音、衰减
    - 实现**动态音效逻辑**（如走路随机脚步声、环境复合音效）
    
- **特点**：可视化节点编辑、可暴露参数给蓝图 / C++ 控制
- **类比**：**预制件 / 配方（用铁做成弹簧、螺丝）**

### 3. MetaSound（UE5 新一代音频系统）

- **定义**：UE5 替代 Sound Cue 的**高性能 DSP 音频系统**。
- **作用**：
    
    - 完整底层 DSP 控制、模块化音频合成
    - 实时生成、参数自动化、更精准时序控制
    
- **特点**：比 Sound Cue 更强大、更灵活、性能更好
- **类比**：**音频 “材质编辑器”**（可编程、高度自定义）

---

## 二、管理与控制类（分组、混音、全局控制）

### 1. Sound Class（声音类）

- **定义**：**音频分组管理资产**，用于批量控制同类声音Epic Games。
- **作用**：
    
    - 按类型分组：音乐、音效、对话、UI 等
    - 统一控制：音量、音调、滤波器、优先级、并发数
    - 配合 **Sound Mix** 实现**动态混音**（如战斗时压低背景音乐）
    
- **特点**：可分层级（父 / 子类）、全局影响、运行时可动态调整Epic Games
- **类比**：**音频文件夹 + 总控开关**

### 2. Sound Attenuation（声音衰减）

- **定义**：**3D 空间音频规则资产**。
- **作用**：
    
    - 控制**距离衰减**（内半径 / 外半径）
    - 空间化（3D 定位）、空气吸收、遮挡 / 穿透效果Epic Games
    - 混响发送、立体声 / 全景声 pansUnreal Engine 5.6
    
- **特点**：可复用、可被 Sound Cue/Component 引用
- **类比**：**声音在空间中的传播物理规则**

### 3. Sound Concurrency（并发规则）

- **定义**：**控制同时播放数量**的资产。
- **作用**：
    
    - 限制同类型声音最大并发数（如最多 5 个脚步声）
    - 超出时：停止最旧、最低优先级、最远声音
    
- **目的**：防**声音爆音 / 卡顿 / 资源耗尽**

---

## 三、场景播放与实例（运行时）

### Audio Component（音频组件）

- **定义**：**Actor 上的播放组件**，是**场景中真正发声的实例**。
- **作用**：
    
    - 附加到 Actor，在 3D 空间播放 Sound Wave / Sound Cue
    - 运行时控制：播放 / 暂停 / 停止 / 淡入淡出 / 音量 / 音调
    - 承载：衰减、空间混合、循环、优先级
    
- **关系**：
    
    - 可播放 **Sound Wave** 或 **Sound Cue**
    - 属于 **Actor 组件**，有位置、可移动
    
- **类比**：**喇叭 / 音箱**（装在物体上发声）

---

## 四、总线与混音（音频路由）

### 1. Audio Bus / Submix（音频总线 / 子混音）

- **定义**：**信号路由与效果处理节点**。
- **作用**：
    
    - 把多类声音汇总到一条总线（如 “所有环境声”）
    - 统一加效果：混响、EQ、压缩、失真
    - 分层混音结构Epic Games
    
- **特点**：UE5 新音频引擎核心，替代旧 Sound Class 混音

### 2. Sound Mix（声音混合）

- **定义**：**运行时动态混音规则**。
- **作用**：
    
    - 场景 / 状态切换时改变 Sound Class 音量 / 效果
    - 例：菜单→游戏→过场时音乐 / 音效音量变化
    
- **用途**：**音频状态机**

## 五、核心概念对比（一眼看懂）

表格

|类型|层级|核心职责|可播放？|动态逻辑|复用性|
|:--|:--|:--|:--|:--|:--|
|**Sound Wave**|素材层|存储原始音频|✅ 直接播|❌ 无|✅ 高|
|**Sound Cue**|逻辑层|组合 / 随机 / 处理音频|✅ 可播|✅ 强|✅ 高|
|**MetaSound**|高级逻辑|DSP 合成 / 生成 / 精准控制|✅ 可播|✅ 极强|✅ 高|

|**Attenuation**|空间层|3D 衰减 / 空间 / 遮挡|❌ 否|❌ 静态|✅ 高|
|**Audio Component**|实例层|场景中发声 / 控制|✅ 是实例|✅ 实时控|❌ 场景实例|

## 六、一句话总结区别

- **Sound Wave** = **音频文件本身**（素材）
- **Sound Cue / MetaSound** = **音效逻辑 / 处理**（加工）
- **Sound Class / Bus** = **分组混音总控**（管理）
- **Audio Component** = **场景里的喇叭**（播放实例）

**典型工作流**：

导入 WAV → 做成 Sound Wave → 用 Sound Cue 组合逻辑 → 指定 Sound Class 和 Attenuation → 用 Audio Component 在场景播放。

#### 1. 选择已变化时 (On Selection Changed) —— **最常用**

这是最重要的事件。当玩家点击下拉框并选择了一个不同的选项（比如从“窗口模式”切到了“全屏模式”）时，这个事件就会触发。

- **用法：** 点击旁边的 **“+”** 号，它会直接跳到蓝图图表并生成一个事件节点。
    
- **参数含义：**
    
    - **Selected Item (字符串):** 玩家刚刚选中的文本内容（例如 "GBT2706"）。
        
    - **Selection Type (枚举):** 告诉你是怎么选中的（是玩家手动点选的，还是程序代码自动设定的）。
        
- **实际案例：**  
    在这里写逻辑：如果选中的是“全屏”，就执行 Set Fullscreen Mode 指令。
    

---
#### 2. 打开时 (On Opening)

当玩家点击下拉框，**下拉列表弹出来的那一瞬间**触发。

- **用法：** 点击 **“+”** 号生成事件。
    
- **使用场景：**
    
    - **动态刷新：** 比如你是一个“显示器输出”的选择框。你可以在这个事件里写逻辑，先 Clear Options（清空选项），然后重新获取电脑当前连接了几个显示器，再把最新的名字 Add Option 进去。这样能保证玩家打开菜单时看到的是最实时的数据。
        
    - **播放音效：** 点击下拉框时播放一个“咔哒”的 UI 打开声音。
        
---
#### 3. 生成控件事件时 (On Generate Widget Event) —— **进阶用法**

这个和上面两个不一样，它左边是一个“链接/绑定”图标，而不是“+”号。它用于**自定义下拉列表里每一行的长相**。

- **默认情况：** 如果你不动它，下拉列表里每一行就是一段枯燥的白字文本。
    
- **用法：**
    
    1. 点击“绑定” -> “创建绑定”。
        
    2. 它会生成一个函数。
        
    3. 你需要预先做另一个小 UI 控件（比如 WBP_MyComboItem），在这个函数里动态创建并返回这个小控件。
        
- **使用场景：**  
    如果你希望下拉列表里的每一行不仅有文字，还有图标、特殊的底色、或者是鼠标悬停时的发光效果（就像《黑神话》里那种带有水墨底纹的选项），就需要用到这个。

### 1. 基础显示设置 (Display & Resolution)

这些节点控制窗口如何呈现。

- **Set Screen Resolution (设置屏幕分辨率)：** 输入一个 IntPoint（如 1920x1080）。
    
- **设置全屏模式（设置全屏模式）：**
    
    - 0： 全屏（全屏）
        
    - 1: 窗口全屏/无边框 (Windowed Fullscreen)
        
    - 2： 窗口（窗口）
        
- **Set VSync Enabled (设置垂直同步)：** 布尔值（开启/关闭）。
    
- **Set Frame Rate Limit (设置帧率上限)：** 浮点数（如 60.0, 144.0）。设置为 0 表示不限帧。
    

---

### 2. 画质细节设置 (Scalability Quality)

这就是你截图中“阴影”、“贴图”、“特效”等选项对应的节点。**注意：** 参数通常是整数，范围从 **0 (低) 到 4 (影视级)**。

- **Set View Distance Quality (可视距离质量)**
    
- **阴影质量（Set Shadow Quality）**
    
- **Set Post Processing Quality (后处理质量)** —— 包含动态模糊、环境光遮蔽等。
    
- **贴图质量（Set Texture Quality）**
    
- **Set Visual Effect Quality（特效质量）**
    
- **植被质量（Set Foliage Quality）**
    
- **着色质量（Set Shading Quality）**
    
- **Set Global Illumination Quality (全局光照质量)** —— UE5 新增。
    
- **Set Reflection Quality（反射质量）**—— UE5 新增。
    
- **Set Overall Scalability Level (设置整体画质等级)：** 这是一个“一键设置”，会自动调整上面所有的项（如一键设为“中”）。
    

---

### 3. 获取当前设置 (Getter Nodes)

在初始化 UI 时，你需要这些节点来让按钮显示当前的正确状态。

- **Get Last Confirmed Screen Resolution (获取最后确认的分辨率)**
    
- **Get Fullscreen Mode (获取全屏模式)**
    
- **Get Texture Quality (获取贴图质量)** —— (其他质量项同理，都有对应的 Get 节点)。
    

---

### 4. 最关键的节点：应用与保存 (Execution)

**如果你只调用了上面的 Set 节点，画面是不会有任何变化的！** 你必须调用以下节点来生效：

- **Apply Settings (应用设置)：** 核心节点。它会立即根据当前的内存数据修改游戏画面。
    
- **Apply Resolution Settings (仅应用分辨率设置)：** 专门用于只修改分辨率和窗口模式。
    
- **Save Settings (保存设置)：** 将当前的配置写入到磁盘上的 GameUserSettings.ini 文件中。这样下次启动游戏时，设置才不会丢失。
然后对这个对象调用节点，修改相应设置

# 12.子类蓝图与父类
![](图片/UE/学习/学习概念/IMG-20260301171509036.png)
**它就是蓝图版的 Super::BeginPlay();**。

还记得你刚才在 C++ 代码里写的这一行吗？

```cpp
void AMy_Player::BeginPlay()
{
    Super::BeginPlay(); // <--- 就是这一行！
    // ...
}
```

**“将调用添加到父函数” (Add call to parent function)** 的作用完全一样。

### 详细解释

#### 1. 为什么要用它？（继承的逻辑）

在虚幻引擎中，类是**分层级**的（父类 -> 子类）。

- **父类（比如你的 C++ 类 AMy_Player）**：在 BeginPlay 里写了“设置初始血量为 100”。
    
- **子类（比如基于这个 C++ 创建的蓝图 BP_MyPlayer）**：你想在 BeginPlay 里加一个“播放出生特效”。
    

如果你在蓝图里直接拉一个 Event BeginPlay 节点并连上“播放特效”，引擎默认会认为：**“哦，你想完全重写（Override）父类的逻辑。那你父类里写的‘设置血量’我就不执行了，只执行你的‘播放特效’。”**

后果就是：特效播放了，但血量是 0（因为父类代码没跑），角色直接死了。

#### 2. 这个按钮的作用

当你点击“将调用添加到父函数”后，蓝图里会多出一个橙色的节点（通常叫 Parent: BeginPlay）。

你应该把它连在你的逻辑**最前面**（或者最后面，看需求）：

 **[事件开始播放]** ---> **[父：开始播放]** ---> **[播放特效]**

这样执行顺序就变成了：

1. 先去执行父类（C++）里的代码（设置血量）。
    
2. 再回来执行子类（蓝图）里的代码（播放特效）。
    

### 什么时候必须用？

- **几乎总是需要！**
    
- 特别是在 **BeginPlay**（开始游戏）、**Tick**（每帧更新）、**OnPossess**（控制角色）这些核心事件上。
    
- 因为虚幻引擎底层的 Actor 或 Character 类在这些函数里做了很多你看不见的初始化工作（比如初始化移动组件、物理模拟等）。如果你把父函数调用删了，你的角色可能动不了，或者直接卡死。
    

### 总结

- **在 C++ 里**：你手写 Super::函数名(); 来保留父类功能。
    
- **在蓝图里**：你右键点击“将调用添加到父函数”来保留父类功能。
    

**如果你发现你的蓝图角色有些奇怪的 Bug（比如血量不对、移动不了），第一件事就是检查：是不是重写了某个事件，但忘记连上这个橙色的“父函数”节点了。**

### 变量复制：
None：不复制，仅在本地生效
Replicated：变量会从**服务器主动同步到所有客户端**，但客户端**无法主动修改并回传**到服务器。
RepNotify：在 `Replicated` 基础上(==叠加==，多个触发)，当变量值在客户端被服务器更新时，会自动触发一个自定义事件，复制，广播，并触发一个函数(`RepNotify` 事件**仅在客户端触发**)，做变化反应，“**客户端收到复制更新后** 才触发”
