UE5本质上是一个顶级3D引擎，用来做2D游戏（尤其是像素风）时，很多默认开启的“高大上”功能反而会变成累赘。既然你已经解决了物理步高的问题，为了让你少走弯路，这里列出几大**“UE做2D游戏必踩的坑”**及其解决方案：

### 1. 画面模糊与变色（纹理设置坑）

你会发现导入的像素画图片在游戏里看起来糊糊的，或者颜色变灰、发白。

- **Filter（过滤器）**：默认是 Bi-linear（双线性过滤），这会让像素变糊。
    - **解决**：打开纹理图片，将 **Texture Group** 设为 2D Pixels (unfiltered)，或者手动将 **Filter** 设为 Nearest（邻近采样）。
        
- **Compression（压缩）**：默认的DXT压缩会产生噪点。
    
    - **解决**：将 **Compression Settings** 设为 UserInterface2D (RGBA) 或 VectorDisplacementmap (无损)。
        
- **Mipmaps**：远处的贴图会自动变糊。
    
    - **解决**：将 **Mip Gen Settings** 设为 NoMipmaps。
        
- **变色/发灰**：这是因为UE默认开启了自动曝光（Eye Adaptation）和Tone Mapper。
    
    - **解决**：在场景中放一个 **PostProcessVolume**（后期盒子），勾选 Infinite Extent（无限范围），将 **Exposure**（曝光）设为 Min=1, Max=1（手动固定）。如果要还原纯粹的PS色值，还需要在后期设置里把 Tone Curve 调成线性（但这比较复杂，通常关掉自动曝光就够了）。
        

### 2. 瓦片地图的“幽灵线”（Tile Map Visual Artifacts）

在游戏运行时，当你移动相机，瓦片之间偶尔会闪烁出一条细细的透明线或杂色线。

- **原因**：这是浮点数精度和渲染时的抗锯齿（AA）导致的纹理采样溢出。
    
- **解决**：
    
    1. **首选**：在你的瓦片集源文件（Sprite Sheet）中，给每个瓦片周围留 **Padding（出血/填充）**。比如32x32的格子，要在素材上画成34x34，把边缘像素重复延伸出去一圈。
        
    2. **引擎设置**：在项目设置中，搜索 **Anti-Aliasing**，对于像素游戏，尽量不要用 TSR 或 TAA（会让画面变糊且有拖影），改用 FXAA 甚至 None。
        

### 3. Z轴深度冲突（Z-Fighting / 前后遮挡）

你会发现有时候角色明明在树前面，却突然闪到了树后面，或者两个重叠的物体疯狂闪烁。

- **原因**：2D游戏通常使用半透明材质（Translucent）。在渲染半透明物体时，UE需要知道谁在前谁在后。如果Y轴（深度轴）坐标完全一样，引擎就不知道该先画谁了。
    
- **解决**：
    
    1. **物理分层**：养成习惯，背景层Y=100，墙体层Y=0，前景装饰Y=-100。
        
    2. **PaperZD的排序**：PaperZD组件里通常有 **Translucency Sort Priority**（半透明排序优先级）。如果不希望通过改Y轴来解决（比如都在Y=0平面），就要手动设置这个整数值，数值越大越靠前。
        

### 4. 角色奇怪的旋转（Lock Rotation）

当你撞到墙或者物理模拟开启时，你的2D纸片人角色可能会突然像3D物体一样“倒下”或者歪掉。

- **解决**：
    
    1. 在 **CharacterMovement** 组件中，找到 **Constrain to Plane**（你已经做过了）。
        
    2. **关键补充**：在角色胶囊体或Mesh的物理设置里，找到 **Lock Rotation**。通常对于2D游戏，你要锁定 X 和 Y 轴的旋转，只允许 Z 轴旋转（如果你需要转身），或者全部锁定（如果你只通过Flipbook翻转图片来转身）。
        

### 5. 正交相机 vs 透视相机（Camera Type）

这是一个经典的抉择坑。

- **正交（Orthographic）**：
    
    - 优点：真正的2D视图，没有近大远小，物体大小恒定。
        
    - 坑：在UE 5.3之前，正交相机的光照、阴影和特效支持非常差（几乎不可用）。虽然UE 5.5修复了很多，但**Lumen**（动态全局光照）在正交视角下可能依然会有奇怪的表现或性能消耗。
        
- **透视（Perspective）**：
    
    - 优点：光照、Lumen、特效完美支持。
        
    - 坑：有近大远小。如果不希望画面变形，需要把相机的 **Field Of View (FOV)** 调得很小（比如 10-20度），然后把相机拉得**非常远**。这叫“伪正交”视角。
        

### 6. 流明（Lumen）与 性能杀手

UE5默认开启Lumen。对于一个2D游戏来说，Lumen是性能杀手，而且可能导致画面出现奇怪的“噪点”或光斑（因为Lumen是为3D空间反射设计的）。

- **解决**：如果是纯2D手绘风格，不需要实时光照反弹，请在项目设置里把 **Global Illumination** 和 **Reflections** 从 Lumen 改为 None 或 Screen Space。这能让你的2D游戏帧数暴涨。
    

### 7. 碰撞体胶囊 vs 盒子（Capsule vs Box）

UE的角色默认必定带一个胶囊体（Capsule Component）。但很多2D游戏（如马里奥）需要的是方形判定。

- **坑**：胶囊体底部是圆的，导致角色站在悬崖边时会“滑”下去，或者站在很窄的方块上站不稳。
    
- **解决**：
    
    - 通常我们**保留胶囊体**作为根组件（Root），但把它的半径设得比角色窄一点。
        
    - 虽然不能把根组件换成Box，但你可以通过调整 Perch Radius Threshold（栖息半径阈值）或者简单地通过关卡设计（避免极窄的立足点）来规避。
        
    - PaperZD通常沿用Character类的胶囊体逻辑，如果你非要完美的方形碰撞，可能需要完全重写Pawn逻辑（不推荐新手做）。
        

### 8.导航网格体(UE5 的导航本质)
永远记住：**UE5 的 NavMesh 是 3D 的，它是基于体素（Voxel）计算的。**  
即使你做的是 2D 游戏，导航系统依然把世界看作 3D 的。它不认识“图片”，它只认识“碰撞体（Collision）”。

用处：用来配合敌人AI移动或者追击，蓝图节点AI_Move_To , 需要放置==导航网格体体积+构建路径==
设置：项目设置->导航网格体或导航系统
注意：若导航系统中没有设置代理，那么就默认使用导航网格体中的默认代理来生成网格体
**“导航网格体（Navigation Mesh）”是【画板的默认属性】，而“导航系统（Navigation System）里的代理”是【你要在画板上画的具体角色】。**
##### 一、 关键知识点（参数调优）
这次调试中，决定生死的三个核心参数（都在项目设置里）：

1. **Cell Size（单元大小）**：**决定“分辨率”**
    - **作用**：把地图切成多大的小方块去计算。
    - **坑点**：**千万别设为 1.0！** 虽然你想要高精度，但 1.0 会导致计算量爆炸，引起内存溢出或静默失败（Silent Fail），直接导致网格不生成。
    - **推荐值**：像素游戏一般用 **4.0 ~ 5.0**。
        
2. **Agent Radius（代理半径）**：**决定“离墙多远”**
    - **作用**：告诉系统你的角色有多胖。
    - **坑点**：**不能小于 Cell Size。** 如果 Radius(2.0) < Cell Size(5.0)，会出现采样混叠，导致本来能走的路断开、不连续。
    - **推荐值**：建议是 Cell Size 的 **2倍** 左右（例如 Cell=4, Radius=8）。
		
3. **Agent Max Step Height（最大步高）**：**决定“能不能上墙”**
    - **作用**：定义多高的障碍物算“台阶”。
    - **坑点**：**默认值是 35**（为了 3D 游戏的楼梯）。在 2D 游戏里，这会导致 AI 判定墙壁也是路，直接生成到墙头上。
    - **推荐值**：2D 游戏直接改为 **1.0 ~ 5.0**，彻底禁止爬墙。

##### 二、 必须避开的“天坑”
#### 1. 幽灵网格（复制重铸导航网格）
- **现象**：绿网格颜色变深、左上角文字重叠乱码、修改设置不生效。
    
- **原因**：当你在项目设置里反复增删 Supported Agents，或者在 Static/Dynamic 模式间切换时，场景里旧的 RecastNavMesh Actor **不会自动删除**。
    
- **解决**：去大纲视图（Outliner）搜 "Recast"，**全删掉**，再点构建。一个关卡同一种代理只能有一个 RecastNavMesh。
    
#### 2. Z 轴的陷阱（平坦陷阱）
- **现象**：TileMap 明明有碰撞，但就是不生成网格。
- **原因**：
    - NavMeshBoundsVolume 太扁了，没包裹住 Z=0 的地面。
    - 地面碰撞体太薄，或者位置就在 Z=0，而体积底部也在 Z=0，浮点数误差导致判定在“体积外”。
- **解决**：把 NavMeshBoundsVolume 的 Z 轴拉大（比如 -500 到 +500），确保绝对包裹。
    
#### 3. 碰撞体缝隙（Collision Gap）
- **现象**：看起来路很宽，但网格断开了。
- **原因**：实际的“通过宽度” = 两墙距离 - 2 * Agent Radius。如果结果小于 0，系统就认为过不去。
- **解决**：要么把墙的碰撞画小点，要么把 Agent Radius 改小点（但别小于 Cell Size）。

##### 三、 2D 项目的独家技巧
###### 技巧 A：隐形地板法 (The Invisible Floor)
- **场景**：如果不想给每一块地砖都在 TileSet 里画碰撞（太累，且容易挡子弹）。
- **做法**：在 TileMap 下面垫一个巨大的、压扁的 **Cube**，设置材质隐形，但开启 Can Ever Affect Navigation。
- **好处**：导航网格生成极其平整、稳定，不受地砖拼接缝隙影响。
	
###### 技巧 B：动态生成（运行时生成：动态）
- **场景**：开发阶段经常改地图。
- **做法** ：项目设置 -> Navigation Mesh -> Runtime Generation 设为 Dynamic。
- **好处**：不用每次都点“构建路径”，拖动一下体积或修改碰撞，网格实时更新，所见即所得。

##### 总结检查清单（Checklist）
下次遇到问题，按这个顺序查 1 分钟就能搞定：
1. **看 Z 轴**：NavMeshBoundsVolume 包住地面了吗？
2. **看 大纲**：有没有重复的 RecastNavMesh？有就全删。
3. **看 碰撞**：地面有碰撞吗？（按 Alt+C 查看）。
4. **看 数值**：
    - Cell Size 不要太小 (>= 4.0)。
    - Radius 不要比 Cell Size 小。
    - Step Height 设小点防止上墙。

### 总结清单（避坑指南）
1. **关掉步高**（你已经做了，Max Step Height = 0），敌人AI寻敌的步高不能设置为0，容易被东西阻挡，重复计算，导致一顿一顿的行走
2. **关掉摩擦力**（物理材质 Friction = 0，防止卡墙）。
3. **纹理设置(导入后马上设置)**：Filter设为Nearest，关闭Mipmaps。
4. **抗锯齿**：关掉 TAA，用 FXAA 或 None。
5. **相机**：如果你发现光照不对劲，检查是不是正交相机的问题，或者尝试用长焦距的透视相机。
6. **灯光**：如果不需要复杂的动态光，关掉 Lumen和自动曝光。
7. **AI_Move**：不能放入Tick中，因为这是一个持续性动作。
8. **重构导航**： 对地图做出了修改，如果没有自动构建导航路径，就需要在顶部菜单栏->构建->构建路径
9. **导航网格体的精度问题**：需要在项目设置里，调整代理的步高，步长，半径，坡度
