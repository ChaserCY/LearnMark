# 冷更系统结构
```
[游戏启动] -> 打开 EntryLevel（空白关卡）
               │
               ▼
[初始化 Puerts JsEnv] -> 在GameInstance Init时（读取本地热更目录，时期较早）
			   │
               ▼
[C++ HotUpdateSubsystem] -> 本地与远端 version.json进行校验
		       |
               ▼
               │
      ┌────────┴────────┐
      ▼                 ▼
[版本一致/无需更新]     [版本不一致]
      │                 │-> HTTP GET 下载远端 bundle.js 与新 version.json
      │                 │-> 覆盖Content/JavaScript/buendle.json文件内容
      │                 │-> 覆盖Saved/PersistentDownloadDir/version.json文件内容
      └────────┬────────┘
               |
               ▼
[执行 bundle.js] -> 调用 blueprint.mixin 混入蓝图
               │
               ▼
[OpenLevel] -> 进入正式游戏关卡 Main_Map（带 Mixin 逻辑的 Actor 正常生成）
```
==注意==： JavaScript文件夹中的文件，只有自己的写的可以删，其他的文件最好一起打包出去，因为虽然业务代码打包进了 bundle.js，但 Puerts 插件在底层初始化、处理对象映射、垃圾回收（GC）以及和 C++ 交互时，依然要依赖 puerts 文件夹里的基础底层 JS 脚本。

# 编辑器打包
需要在TypeScript文件夹下新建一个综合的打包文件bulid.js，文件里面涉及到的import的文件==会自动包含==
1. (前提)项目目录安装包：==npm install esbuild --save-dev==
2. (前提)编写好==build.js文件==在==TypeScript文件夹==下
3. (开发时，可以进行类型检查)命令：==npx tsc==(整体全部编译ts->js) 或者  ==npm start== (编辑时，增量编译ts->js) 或者  ==npx tsc --noEmit==(只做类型检查，不生成文件)
4. (无错时，全体解析编译)使用命令：==node build.js==   实行ts代码编译打包至一个bundle.js文件
![](图片/UE/PuerTs/热更系统运行全景流(三天)/IMG-20260915171051648.png)
```js
build.js文件
const esbuild = require('esbuild');  
  
async function build() {  
    try {  
        await esbuild.build({  
            entryPoints: ['./MainGame.ts'],           // 指向你当前的 MainGame.ts 入口  
            bundle: true,                               // 开启打包合并  
            outfile: '../Content/JavaScript/bundle.js', // 输出到同级目录下的 Content/JavaScript/bundle.js            platform: 'node',                           // 平台设为 node            format: 'cjs',                              // 模块化格式为 CommonJS            sourcemap: true,                            // 生成 map            external: ['ue', 'puerts'],                 // 排除 ue 和 puerts        });  
        console.log("----------------------------------------");  
        console.log("[Esbuild] 成功打包为单文件: Content/JavaScript/bundle.js");  
        console.log("----------------------------------------");  
    } catch (error) {  
        console.error("[Esbuild] 打包失败：", error);  
        process.exit(1);  
    }}  
  
build();
```

## 冷热的底层区分
- **冷更**是：**操作系统级别**的刷新，靠“杀死整个游戏进程再拉起”来重载代码和内存；
- **热更**是：**虚拟机级别**的刷新，在“保持游戏主进程不退”的前提下，
- 通过清空旧场景->重启 V8 虚拟机->重新执行 @mixin 原型注入，达成与重启游戏完全一致的效果，但玩家感知不到进程关闭。(有个空的中间过渡关卡)

# 拓展
1. 多级更新：资源（AssetBundle / UE 的 Pak patch）+ 配置表 + 脚本，分层各自独立版本
2. 清单 + 增量：一个 manifest 列出每个文件的 hash，客户端比对后只下变化的文件（你的HOTUPDATE-PLAN.md 里也是奔着这个方向设计的，现在是简化的单文件全量）
3. 校验 + 原子写 + 回滚：下载完先校验哈希/签名，写临时文件再 rename，保留上一版本可回退
4. 灰度/回滚开关：CDN 上按版本号或白名单放量，出问题能一键回滚
