### 对打包后的游戏进行性能分析
#### 第一步：正确打包项目 (Packaging)

1. 在虚幻编辑器顶部，点击 **Platforms**（平台）菜单
    
2. 找到你的目标平台（例如 Windows），将 **Binary Configuration**（二进制配置）设置为 **Development
    
3. （可选，推荐）进入 **Project Settings** -> **Packaging** 页面：
    
    - 展开高级选项（Advanced），勾选 **Include Debug Files**这会生成 .pdb 调试符号文件，有助于在 Insights 中还原更详细的 C++ 函数调用栈
        
4. 点击 **Package Project**，选择路径并完成打包
    

---

#### 第二步：准备接收端 (Unreal Insights)

在启动打包好的游戏之前，需要先启动 Unreal Insights：

- 打开 [引擎安装路径]/Engine/Binaries/Win64/UnrealInsights.exe
    
- 让它在后台保持运行，它会自动在后台开启一个 Trace Server（默认监听 1980 端口）
    

---

#### 第三步：通过命令行带 Trace 参数运行游戏

打包出来的游戏默认不会自动向 Insights 发送数据。你需要通过**命令行参数**来告诉游戏“把数据发送到哪里”以及“需要录制哪些内容”

以 Windows 平台为例：

1. 找到你打包出来的实际运行文件（注意：通常位于 [打包目录]/Windows/MyGame/Binaries/Win64/MyGame-Win64-Development.exe，==而不是根目录下的快捷启动器）==
    
2. 在该目录下打开 **命令提示符（CMD）** 或 **PowerShell
    
3. 输入以下命令启动游戏
    ![](图片/UE/工具/性能分析工具/IMG-20260609172748650.png)
    ```Bash
    //当前目录的启动程序
    .\ArcheryBattle_5_6_1.exe "-trace=cpu,gpu,frame,bookmark" -tracehost=127.0.0.1 -statnamedevents
    ```
    
    - **-trace=...**：指定录制的通道。如果要分析蓝图函数耗时，请务必写为 -trace=default,AssetLoadTime。
        
    - **-tracehost=127.0.0.1**：发送给本地运行的 Insights。如果游戏运行在移动端（Android/iOS）或主机上，请把 127.0.0.1 替换为**你运行 Insights 那台 PC 的局域网真实 IP**（例如 192.168.1.100）。
        
    - **-statnamedevents**：将命名的事件传入 Trace
        

---

#### 第四步：在 Insights 中实时或离线分析

#### 1. 实时分析（推荐）

当带参数运行游戏后，打开之前启动的 Unreal Insights 窗口，你会发现在 **Session Browser** 列表里多了一条状态为 **LIVE** 的会话

- **双击该 LIVE 会话**，你就可以一边玩游戏，一边在 Insights 里看着实时的 CPU/GPU 线程耗时更新
    

#### 2. 离线分析

如果你的测试环境无法通过网络连接到 Insights 电脑，可以去掉 -tracehost 参数，只保留 -trace=... 参数运行游戏。

- 游戏运行完毕后，会在打包文件夹的 [GameName]/Saved/Profiling/ 路径下自动生成一个 .utrace 格式的离线文件
    
- 你可以随时把这个文件拷贝到任何装有 Unreal Insights 的电脑上，直接拖入软件中进行离线分析。
    

---

#### 第五步：Development 包中的调试实用技巧

在 Development 版本的包中，你可以充分利用以下技巧来让分析事半功倍：

1. **利用控制台实现“动态开关录制”**：  
    如果不想一启动游戏就录制（防止 Trace 文件过大），可以在启动参数里加上 -traceautostart=0
    
    - 游戏运行后，随时按 **~ 键** 打开控制台，输入 **Trace.Start cpu,gpu** 开始录制
        
    - 录制完一段后，按 ~ 输入 **Trace.Stop** 停止录制。
        
2. **遇到卡顿即时“打标（Bookmark）”**：  
    在体验测试时，只要感觉画面明显卡顿了一下，立刻按 **~ 键** 输入 **Trace.Bookmark MySpike
    
    - Insights 的时间线上会立刻出现一条醒目的蓝色虚线。你可以直接拖动时间线到该虚线位置，专注于分析这“卡顿一帧”的调用栈，而不需要在几十万帧的历史记录里大海捞针。

## 各个模块意思，面板
![](图片/UE/工具/性能分析工具/IMG-20260609162002959.png)
### 1. 顶栏左侧：会话与标签页管理 (Session & Tabs)

- **作用**：用于在不同的分析视图之间切换。
    
- **说明**：
    
    - **Session**：点击可以返回“会话浏览器”，在此处可以查看、加载或导入其他的 .utrace 性能数据文件。
        
    - **Timing Insights**：当前处于激活状态的性能时间线分析标签页。支持打开多个不同的 trace 文件进行对比。
        

---

### 2. 左上角快捷工具栏：面板显示开关 (Toggle Buttons)

- **作用**：控制界面中各个子面板的显示与隐藏，以便你自定义最适合当前分析任务的布局。
    
- **各个按钮对应控制的面板**：
    
    - **Frames**：显示/隐藏最上方的“帧时间轴”（即显示 100ms, 60fps 等刻度的区域）。
        
    - **Timing**：显示/隐藏中间占据最大面积的“线程/时间线轨道视图”。
        
    - **Timers**、Counters、Log 等：分别对应控制右侧和下方各个统计面板的开关。
        

---

### 3. 时间线中部：轨道过滤器 (Track Filters)

- **作用**：对中间时间线上的众多线程轨道进行筛选和管理，避免信息过载。
    
- **说明**：
    
    - **All Tracks / CPU/GPU / Other / Plugins**：虚幻引擎在运行时会产生几十个 CPU 线程，该下拉菜单允许你快速隐藏不关心的线程，只保留最核心的轨道（例如 GameThread、RenderThread 或 RHIThread），从而让分析界面更加清晰。
        

---

### 4. 左下方：日志输出面板 (Log Panel)

- **作用**：展示在进行数据追踪（Trace）期间，游戏或编辑器输出的系统日志（即 UE_LOG 打印的内容）。
    
- **分析妙用**：
    
    - **时间线对齐**：日志面板中记录的时间戳与上方的时间轴是完全同步的。
        
    - **双击定位**：如果在测试过程中发生了网络连接、资产加载或特定逻辑事件，你可以在该面板中找到对应的 Log（例如图中的 LogEOS...），**双击该条日志**，上方的时间线会自动跳转并缩放到该日志打印的具体时刻，非常便于将日志事件与性能卡顿点进行关联分析。
        

---

### 5. 右上方：数据分析标签页切换 (Analysis Tab Switcher)

- **作用**：在右侧的统计数据视图之间进行切换。
    
- **说明**：
    
    - **Timers**：当前选中的标签页。以表格形式显示所有 CPU/GPU 函数/事件的聚合耗时统计（对应区域 6）。
        
    - **Counters**：计数器面板。用于查看各种数值型统计数据，例如 Draw Call 数量、渲染三角形数量、瞬时内存分配大小等。
        

---

### 6. 右侧中部：计时器统计表 (Timers Table)

- **作用**：展示在**当前选中时间范围**内，所有被调用的函数（Timer）的统计数据，是定位高耗时函数最核心的面板。
    
- **核心列数据解释**：
    
    - **Name**：函数或 Profiler 事件的名称。
        
    - **Count**：该函数在当前选中时间范围内被调用的总次数。
        
    - **Incl (Inclusive Time)**：**包含时间**。表示该函数自身运行耗时，**加上**它内部调用的所有子函数耗时的总和。
        
    - **Excl (Exclusive Time)**：**专属/自身时间**。表示扣除掉它内部调用的子函数耗时后，该函数自身纯逻辑消耗的时间。通常可以通过对 Excl 进行降序排列，快速找出算法逻辑最慢的那个函数。
        

---

### 7. 右下方：调用关系面板 (Callers / Callees)

- **作用**：展示你在区域 6（Timers 列表）中选中的那个函数的上下文调用关系（即调用栈的上下级）。
    
- **说明**：
    
    - **Callers（调用者）**：显示是谁在更上层调用了当前选中的函数（父级节点）。
        
    - **Callees（被调用者）**：显示当前选中函数内部又调用了哪些子函数（子级节点）。
        
    - **分析妙用**：当你在右侧 Timers 表中发现一个耗时很长的函数时，通过这个面板可以迅速厘清它是被哪个系统调用的，以及它把时间主要花在了哪些具体的子步骤上，有助于针对性地进行重构和优化。

注意：部分的横条是Wait，受其他进程影响，在等待前一个执行完毕

右上角的Timer，Counters。
Timer：这一帧/时间段中，CPU，GPU的耗时统计(可能包含Wait)，依旧向下逐级嵌套展开

在中部的横向时间轴下，在同一时间上有不同的进程(这些进程在客观上同时运行)，一个进程内的下面部分，是对该进程的子调用拆分，逐级进行，越拆越细，更好看清组成(直观)。

右侧下部分的黄色列表，是你点击中部中的某个片段，直接展开其当前，及其嵌套调用的更底层，相当于图表的直接表格格式(更全更详细)
