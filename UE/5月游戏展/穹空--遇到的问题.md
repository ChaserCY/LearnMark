11. NPC的受伤UI控件组件没有正常显示
	1. UI用户控件内事件，相关变量不能开启“复制”
	2. **NPC 的用户控件转换得到的“控件实例变量”，需要开启复制吗？**   **绝对不能开启复制！必须是普通的本地变量！**  
    原因：每个玩家的电脑上，都生成了一个属于自己屏幕的“纯本地 UI 实例”。如果你把这个 UI 变量设为复制，服务器会试图把它电脑上的 UI 内存地址同步给客户端，客户端一读，发现这个地址在自己电脑上根本不存在，会立刻爆出一屏幕的**空指针报错**。

28. 为什么局域网做创建会话房间时，如果是客户端创建会话，服务器没有反应，如果是服务器创建了会话，那么客户端会重新启动项目设置中的游戏默认地图，这是什么情况
	1. 为什么：在 UE 编辑器里，把测试模式设置成了 **“作为监听服务器运行 (Play As Listen Server)”**，并且玩家数设为了 2。
	2. 什么情况：当你用“作为监听服务器”启动 2 个窗口时，引擎底层已经**自动帮你把客户端连到了服务器上**。你们已经在一个局域网房间里了。此时你去按“创建会话”的 UI：
	     - 现象 1：客户端建房，服务器没反应
		- **底层真相**：客户端玩家 A 觉得不爽，想自己当房主，于是他点击了“创建会话”。
	    - 此时，客户端 A 确实在本地的底层接口（Online Subsystem NULL）注册了一个局域网房间。
	    - 但是，**服务器根本不关心！** 客户端 A 只是服务器手下的一个“打工仔”，打工仔自己去外面开了个公司，老板（服务器）是不会有任何反应的。而且客户端 A 并没有执行跳转地图的操作，所以你觉得什么都没发生。
	    - 现象 2：服务器建房，客户端重启到了默认地图
	    - **底层真相**：服务器（主机）觉得这个房间不好，按下了“创建会话”，并且在成功后执行了 **Open Level (带 ?listen 参数)**。  
	    - **致命瞬间**：当服务器执行 Open Level 重新开新房间时，它会**瞬间掐断当前的局域网连接**。
	    - 客户端突然被服务器踢下线了（Connection Lost）。
	    - 在 UE 的默认网络机制中，**一旦客户端与主机失去连接，引擎会自动把客户端扔回项目设置里指定的“游戏默认地图（Game Default Map）”**。这就是为什么客户端会看起来像“重启”了一样跑到别的地图去了！
	3. 怎么做：“创建房间”和“寻找房间”必须在一个**完全单机、未联网**的“主菜单（Main Menu）”地图里进行测试
		1. 不要再用“监听服务器”模式测试建房 UI 了！
		2. 点击编辑器顶部绿色的“播放 (Play)”按钮旁边的三个点 ...。
		3. 将 **网络模式 (Net Mode)** 修改为 **独立运行 (Play Standalone)**。
	    4. 玩家数设为 **2**。
	    5. 结果：此时弹出的两个游戏窗口是**彻底断开、毫无关系**的单机窗口。这才是测试建房的正确环境！

33. - **场景实况**：玩家 A（客户端）走进了碰撞箱。
- **物理真相**：
    1. 玩家 A 的电脑上，A 的肉体碰到了箱子（**客户端 A 触发**）。
    2. 服务器的电脑上，A 的镜像碰到了箱子（**服务器触发**）。
    3. 玩家 B 的电脑上，B 看到 A 的镜像走进了箱子，物理引擎判定重叠发生（**客户端 B 也触发！**）。
- **灾难后果**：玩家 A 踩了箱子，结果**玩家 A、玩家 B、主机（服务器）的屏幕上同时弹出了 UI！** 玩家 B 会一头雾水：“我明明在挂机，怎么屏幕上弹提示了？”

34. 敌人NPC的Widget控件(2D)没法做到靠近再显示

	2. 只是隐藏视觉，不会隐藏物理碰撞

35. 控件蓝图达到特定时机，想要暂停Tick事件

	2. 使用定时器来代替Tick，并且能暂停定时器的消耗
