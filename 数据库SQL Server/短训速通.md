索引：
	常见的索引类型包括：
1. **单列索引**
    - 只对表中的一列创建索引。
    - 例：给用户表的 `username` 列建索引，加快按用户名查找的速度。
2. **组合索引（多列索引）**
    - 对表中的多列联合建索引。
    - 例：`(last_name, first_name)`，可以加快同时按姓和名查询的速度。
3. **唯一索引（Unique Index）**
    - 索引列的值必须唯一。
    - 例：`email` 列建唯一索引，保证邮箱不重复。
4. **主键索引（Primary Key）**
    - 数据表的主键默认就是唯一索引，同时不能为 NULL。
5. **全文索引（Full-text Index）**
    - 用于对文本数据进行快速搜索，比如查找文章内容中的关键词。


## 1. 数据库基础概念

1. **数据库（Database）**
    - **定义**：数据库是按某种数据模型组织起来的、长期存储在计算机内、有组织的数据集合。
    - **官方说法（SQL Server 文档）**：数据库是一个包含表、视图、存储过程、函数、触发器、索引等对象的容器，用于存储和管理数据。
2. **关系模型相关概念**
    - **关系模式（Relation Schema）**：数据库中一个表的结构定义，包括属性（列）名称和类型。
    - **属性值（Attribute Value）**：某一列在某一元组（行）中的具体值。
    - **元组（Tuple）**：表中的一行记录。
    - **关系操作**：关系代数的基本操作，包括选择（SELECT）、投影（PROJECT）、连接（JOIN）、笛卡尔积（CROSS JOIN）、并（UNION）、差（EXCEPT）等。
    - **主码（Primary Key）**：唯一标识一条记录的属性或属性组合。
    - **外键（Foreign Key）**：用于实现表间关联的属性，参照另一表的主键。
3. **概念模型与数据库设计阶段**
    - **概念模型（Conceptual Model）**：用ER图（实体-关系图）表示现实世界对象及其关系，是数据库设计的第一步。
    - **数据库设计阶段**：
        1. 概念设计：ER图
        2. 逻辑设计：关系模式、范式化
        3. 物理设计：索引、存储、优化
    - **规范化的关系模式 / 范式**：通过消除冗余数据和依赖关系（函数依赖集）来提高数据一致性。常见范式包括 1NF、2NF、3NF、BCNF。

## 2. SQL语言基础（SQL Server 版）

1. **SQL 分类**
    - **DDL（Data Definition Language）**：定义数据库结构
        - `CREATE`, `ALTER`, `DROP`
    - **DML（Data Manipulation Language）**：操作数据
        - `SELECT`, `INSERT`, `UPDATE`, `DELETE`
    - **DCL（Data Control Language）**：权限控制
        - `GRANT`, `REVOKE`
    - **TCL（Transaction Control Language）**：事务控制
        - `COMMIT`, `ROLLBACK`, `SAVEPOINT`
2. **查询语句和条件**
    - **基本 SELECT**：查询列和行
    - **WHERE**：条件过滤，支持 `BETWEEN`、`IN`、判断空值 `IS NULL`
    - **ORDER BY**：排序，可用 `ASC` 或 `DESC`
    - **GROUP BY**：分组统计
    - **HAVING**：分组过滤条件
    - **聚合函数**：`COUNT`, `SUM`, `AVG`, `MAX`, `MIN`
    - **子查询 / 外查询**：查询中嵌套查询
    - **连接（JOIN）**：
        - 内连接（INNER JOIN）
        - 外连接（LEFT/RIGHT/FULL OUTER JOIN）
        - 自连接（SELF JOIN）
    - **集合操作**：`UNION`（去重并集）、`UNION ALL`（并集）
    - **笛卡尔积（CROSS JOIN）**：两表所有组合
3. **SQL Server 特性**
    - **触发器（TRIGGER）**：在表的 `INSERT`, `UPDATE`, `DELETE` 操作发生时自动执行的存储过程
    - **约束**：`PRIMARY KEY`, `FOREIGN KEY`, `UNIQUE`, `CHECK`, `NOT NULL`
    - **ALTER / DROP**：修改或删除表结构

## 3. 数据库完整性与安全性

1. **完整性约束（Integrity）**
    - **实体完整性（Entity Integrity）**：主键不能为 NULL
    - **参照完整性（Referential Integrity）**：外键必须引用存在的主键
    - **用户定义完整性（User-Defined / Domain Integrity）**：通过 CHECK、触发器等约束规则
2. **授权与权限**
    - 控制不同用户对表、视图、存储过程的访问权限
    - SQL Server 使用 `GRANT`, `REVOKE` 管理
3. **安全性（Security）**
    - 数据库账号管理、密码策略、角色权限
    - 数据加密和访问控制

---

## 4. 事务与并发控制

1. **事务（Transaction）**
    - **定义**：一组逻辑操作的集合，要么全部执行，要么全部不执行（ACID 原则）
    - **ACID**：
        - Atomicity（原子性）
        - Consistency（一致性）
        - Isolation（隔离性）
        - Durability（持久性）
    - **事务状态**：活（active）、死（dead）、封（partially committed）、加锁（committed）
2. **锁机制（Locking）**
    - **目的**：控制并发访问，防止脏读、不可重复读、幻读
    - **类型**：
        - 行级锁、表级锁
        - 共享锁（S）、排他锁（X）
    - **三级封锁协议（Three-Level Locking）**：确保事务隔离和一致性
3. **数据库恢复**
    - 使用日志（log）和检查点（checkpoint）恢复数据
    - 避免因事务失败导致的数据不一致

---

## 5. 高级 SQL 与操作

1. **外模式与混合模式**
    - 外模式（External Schema）：用户视图，隐藏底层复杂性
    - 混合模式：结合外模式和内部模式，支持多用户访问
2. **关系操作扩展**
    - **连接种类**：内连接、外连接、多表连接
    - **删除命令（DELETE / DROP）**：删除数据或表
    - **更新命令（UPDATE）**：修改数据
3. **统计与函数**
    - `COUNT(*)`、`SUM()`, `AVG()` 等
    - `BETWEEN`、`IN` 用于过滤
    - 判断空值：`IS NULL`, `IS NOT NULL`
4. **设计原则和规范化**
    - **函数依赖集**：分析属性间依赖
    - **范式目的**：减少冗余，消除异常
    - **不同数据库划分原则**：分库分表、逻辑/物理划分

---

### 📌 总结：串联关系

- **数据库设计**：概念模型 → 逻辑设计（关系模式、范式） → 物理设计
- **表结构**：关系模式 → 属性 → 元组 → 主外键 → 约束完整性
- **操作数据**：SQL DML（SELECT/INSERT/UPDATE/DELETE） → 聚合函数、GROUP BY、HAVING
- **连接与集合**：JOIN（内/外）、UNION、笛卡尔积
- **事务与并发**：事务 ACID → 锁机制 → 并发控制 → 数据库恢复
- **安全性**：授权与权限 → 用户访问控制 → 触发器自动化
